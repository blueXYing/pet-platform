# 宠物平台 V1.0 全链路测试矩阵 v0.1

> 依据：V1.0 产品 SSOT（迟到支付自动退款封板）、技术基线 v0.6、内部 API Contract v0.6、HTTP Contract v0.4、Integration Event Catalog v0.6、Scheduler/Retry/Compensation v0.5。  
> 目标：把已封板业务规则转成研发/测试可执行用例。本文不新增产品规则；对尚未冻结的“人工客服承载方式、微信外部通知具体通道、部分可配置字典”只验证边界，不假设具体实现。

## 1. 优先级定义

```text
P0 = 资金、订单、核销、售后、容量、幂等、权限等上线阻断项
P1 = 重要业务一致性/恢复能力
P2 = 非核心体验、兼容性或低风险边界
```

发布要求：

```text
P0 必须 100% 通过
P1 不允许存在影响核心闭环的未解决失败
```

## 2. 测试环境基线

建议至少准备：

```text
MySQL 8
Redis
拉卡拉 Sandbox / Stub
对象存储 Stub
微信通知 Stub
可注入 FakeClock
可控制 AsyncTaskWorker / OutboxDispatcher 开关
可人工注入渠道 SUCCESS / FAILED / UNKNOWN / timeout
```

所有时间类测试禁止真实等待 10 分钟/30 分钟/24 小时，使用 `Clock`/时间推进能力。
