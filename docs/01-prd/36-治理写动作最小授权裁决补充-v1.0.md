# 治理写动作最小授权：人工裁决补充

状态：人工已批准。来源：用户 2026-10-16 针对"治理面（64 号族）只有查询没有写动作"的遗留项拍板⑥"最小授权"。本文件只登记该授权事实与范围，不新增用户未批准的产品规则；格式沿 33/34 号裁决补充先例。

## 授权内容（最小授权 = 恰好两项）

1. **商家停用（治理面入口）**：运营对商家执行停用（下线）。该能力的**内核与 HTTP 路由已由 33 号裁决（2026-10-15）授权并随 63 号 v0.2 交付**（`merchant.disable` 动作码、`POST /api/v1/admin/merchants/{merchantId}/disable`、SSOT §15 立即下线语义：停止新订单，存量订单继续履约、存量退款/售后继续处理）。本次授权的是**治理页入口**：商家治理页（A-002 Merchant 台账详情）增加"停用"动作入口（带同一人二次确认，22 号补充口径），调用既有 63 号路由。内核零重做、不新增动作码、不新增路由。
2. **券作废（coupon.instance.void）**：运营可作废指定用户的**单张 AVAILABLE 券实例**。守卫口径：
   - 仅 `status='AVAILABLE'` 的实例可作废；`USED`（已核销）/`FROZEN`（被在途订单冻结）/`RISK_FROZEN`/`EXPIRED` 一律拒绝（409）——FROZEN 被订单锁着的券不许作废，防破坏在途单；
   - requestId 幂等（23 号契约）+ 审计（`coupon_ledger` VOID 台账行）+ C 端券桶即时不可见（AVAILABLE 桶过滤既有事实）；
   - 单张作废；批量作废、风控冻结、解冻、手动返还**不在本次授权内**。

## 未被本裁决批准的内容

- **员工处置**（运营对商员工/成员的任何写处置）未授权——SSOT §30 运营侧只读监管口径不变，成员停用/恢复仍是 54 号商家 OWNER 自用面，运营不代行。
- 商家冻结/解冻（merchant.freeze/merchant.unfreeze）、券实例返还、券风控冻结/解冻、批量作废等其他治理写动作不在本次授权内。
- 其余登记在 [CCR-ADM-A005-OPS-001](../../planning/ccr/CCR-ADM-A005-OPS-001.md) 的未授权动作维持不做。

## 执行口径

- 券作废实现修订 65 号契约（增 §4.4，文件名沿用不改）；商家停用治理页入口在 64 号契约中以注记披露（路由权威仍是 63 号 v0.2）。
- 沿用既有机制：requestId 幂等、完整审计、服务端 RBAC 动作码（`coupon.instance.void` 按 AUTH 点分词法新造登记；商家停用沿用既有 `merchant.disable`）、默认关闭装配开关（`pet.coupon.void.enabled` 默认 false；默认值翻转统一走 35 号开关放开裁决）。
- 高权限、二次确认（同一人二次确认，非第二人审批）、完整审计不变；SSOT §9（券规则唯一口径）与既有硬规则不变、不放宽。

## 作废后是否补偿（CCR 登记）

用户已持有的券被作废后要不要赔（补偿/返还/换券）——SSOT 没写，本次裁决也未涉及。按 CCR 纪律登记最小实现 = **不补偿**（作废即终态，无任何自动/手动补偿路径），登记于 [CCR-CPN-VOID-001](../../planning/ccr/CCR-CPN-VOID-001.md)；如需补偿能力须用户另行裁决。
