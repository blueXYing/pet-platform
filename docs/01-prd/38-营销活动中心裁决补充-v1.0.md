# 38-营销活动中心新增裁决补充 v1.0

状态：APPROVED / IMPLEMENTING。2026-10-27 用户裁决：营销活动中心一次性完整交付，不再分期；
平台运营、商家、用户三端全部纳入；买一送一不做；设计稿「团购套餐」改为单次服务列表；
活动详情复用门店详情并增加活动横幅；商家报名、商家发起活动、券活动/批次与 C 端领取全部实现。
本裁决补充不改变 SSOT 既有交易、退款、售后、券生命周期硬规则，只补齐 C 端/运营端/商家端
PRD 已明确但工程此前按“无 V1 后端”裁剪的营销能力。

## 1. 范围

### 1.1 平台运营端

- **Banner/活动位**：首页 Banner、首页活动位（活动钜惠）、商家列表置顶（商家钜惠）；
  标题、图片、角标、跳转类型/参数、生效期、排序、城市、启停。首页 Banner 最多同时启用 3 个；
  落地页失效自动隐藏并告警；跳转参数不得携带手机号等敏感信息。
- **活动会场**：活动主档（标题/副标题/角标/封面/时间/城市/服务分类范围）、参与门店、
  活动标签（新客专享/美容优惠/寄养满减/遛狗月卡等）、活动页 Schema 草稿/发布/回滚。
- **商家报名审核**：平台发起招商活动，商家报名门店与优惠文案，运营审核通过/驳回；
  名额、报名期、活动期；审核通过后门店进入活动会场。
- **商家发起活动审核**：商家创建活动草稿并提交，运营审核发布/驳回；商家活动只能绑定自己的门店，
  不得绑定券活动（券仍由平台运营发放）。
- **券活动/批次**：关联既有券模板（仅无门槛券/满减券），发放对象（全部用户/新用户）、
  每人限领、总发放上限、预算上限、发券期、状态机、主动领取；预算/库存守卫。
- **审计与权限**：全部写动作 requestId 幂等、append-only 审计、RBAC 动作码与数据范围；
  单运营无第二人复核（SSOT §24）。

### 1.2 商家端

- 店铺资料继续维护既有促销等级（1-9 折）、促销文案标题/文案（各 0-100 字），
  C 端门店卡/门店详情/商家钜惠横排展示。
- 可报名活动列表、报名提交/撤回/状态查看。
- 商家发起活动：创建草稿、编辑、提交审核、撤回/取消；审核通过后由平台发布。
- 商家不得自建券模板、不得发券、不得修改券规则。

### 1.3 用户端

- 首页「活动钜惠」活动位；服务 tab「商家钜惠」横排；活动聚合页；活动详情页（Schema 渲染）；
  门店详情活动横幅/促销区；券活动领取；我的优惠券沿用既有页面。
- 活动卡落地只能是：活动会场、门店详情、单次服务详情、服务分类列表、白名单小程序路径。
- 活动/活动位失效自动隐藏，不展示空卡、不跳失效页。

## 2. 设计冲突裁决

1. **团购套餐不做**：设计稿 `96:4355` 的「团购套餐」多服务区块与 V1「仅单次服务，套餐/次卡/普通商品不做」
   冲突。活动详情复用门店详情，服务区改为既有单次服务列表；登记为设计偏差。
2. **买一送一不做**：V1 无赠品/套餐能力，设计稿「买1送1」不落地；登记为设计偏差。
3. **5折/8折**：V1 券类型仅无门槛券/满减券，不新增折扣券。设计中的 5折/8折由商家促销等级 +
   单次服务售价/划线价表达；实际成交价以服务价格为准，不承诺页面上无法兑现的折扣。
4. **新客首单立减**：由券活动/批次的新用户券兑现；未配置券活动时不展示可领取角标。
5. **活动详情页**：复用既有门店详情页，门店属于进行中活动时顶部展示活动横幅；不按活动新建页面。
6. **热更新边界**：后台可配置活动位、活动内容、活动页 Section、参与门店、券活动，
   新活动不需要更新小程序代码；新增一种页面组件类型仍需要发版，组件白名单在契约 71 冻结。

## 3. 硬规则不变

- 单次服务、必须预约、分钟级排期、接送返程 ≥ 上门 +120 分钟、改期最多一次、退款/售后/核销/
  迟到支付/券生命周期规则全部沿用 SSOT；营销不新建订单类型、不新建支付/退款路径。
- 券活动只发放既有券模板实例；下单仍走 61 号冻结/消费/释放；部分退款不返券；全额退款返券。
- 活动/商家促销展示的事实必须来自有效配置；失效落地页自动隐藏，不展示无法兑现的优惠。
- 商家活动/商家报名必须审核；平台活动由运营直接发布（SSOT §24 单运营）。
- 不实现：买一送一、团购套餐/次卡/普通商品、折扣券类型、商家自主发券、商家资金结算/分摊、
  秒杀/拼团/裂变/会员卡/直播、个性化推荐、活动曝光/成交归因报表（本期只做领取计数）。

## 4. 验收

- 运营可创建活动、配置活动位、选择参与门店、编辑/发布活动页；C 端无需发版即可看到新活动。
- 商家可维护促销文案，可在商家端报名/撤回/查看状态，可发起活动并提交审核。
- 用户可在首页/服务 tab/活动聚合页看到活动，进入活动详情/门店详情，领取新用户券并在下单时使用。
- 活动/活动位过期、暂停、落地页失效时 C 端自动隐藏；未知 Schema 组件被跳过且页面不白屏。
- 相关后端测试、架构检查、前端 typecheck/build 通过；无未披露 Contract/Schema/Event 变化。
