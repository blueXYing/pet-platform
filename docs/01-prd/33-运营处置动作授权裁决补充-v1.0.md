# 运营处置动作授权：人工裁决补充

状态：人工已批准。来源：用户 2026-10-15 针对 PR #166（运营交易查询面，63 号契约）交付时披露的遗留处置草案拍板"可以开"。本文件只登记该授权事实与范围，不新增用户未批准的产品规则；格式沿 22/24 号裁决补充先例。

## 授权内容

开启运营处置动作二期（HTTP10 §5.2/§5.5/§5.6 既有草案的实现授权），共三类动作：

1. 渠道查单/重试：对既有业务退款单的渠道查单与渠道动作重试（HTTP10 §5.2 草案；只重试渠道动作，不创建第二张业务退款单）。
2. 异常关单：门店已下线、资质失效、商家失联等被授权异常履约场景下的运营异常关闭订单，语义为异常关闭 + 全额退款（HTTP10 §5.5 草案；不是正常运营代接单）。
3. 商家下线：运营立即下线商家，停止新订单，存量订单继续履约、存量退款/售后继续处理（HTTP10 §5.6 草案；不因存在在途订单直接拒绝下线）。

以上均为既有草案能力，SSOT §4（退款/核销/迟到支付规则）、§15（商家下线规则）、§24（单运营 RBAC）与既有硬规则（含"refund_order 创建后禁止后续核销""未履约售后在 refund_order 创建前仍可核销""核销先成功使当前未履约售后失效""部分退款仅运营售后裁决"）不变、不放宽。

## 执行口径

- 实现修订 63 号契约（不占用 64 号预分配号），契约修订在 PR 中披露。
- 各动作沿用既有机制：requestId 幂等、完整审计、服务端 RBAC 动作码（AUTH-001 提案矩阵第 4/7/8 行拟议码）、默认关闭装配开关。
- 高权限、二次确认（同一人二次确认，非第二人审批，沿 22 号补充口径）、完整审计不变。

## 未被本裁决批准的内容

- 部分退款仍仅运营售后裁决（SSOT 封板不变）；异常关单只做全额退款。
- 不新增导出（CSV/Excel）、不新增代商家接单/代用户支付/手工改渠道事实等 AUTH-001 禁止登记动作。
- 商家冻结/解冻（merchant.freeze/merchant.unfreeze）与账本补偿（benefit-compensation）等其他矩阵行动作不在本次授权内。
