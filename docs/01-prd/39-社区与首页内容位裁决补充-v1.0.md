# 39-社区与首页内容位裁决补充 v1.0

日期：2026-10-28
裁决人：用户
优先级：本补充为 2026-10-28 最新裁决；与既有切片说明冲突处，以本补充为准；不改变 SSOT 中「私信 IM、AI 客服、直播不做」的边界。

## 一、宠友圈社区恢复

用户裁决：「社区后端一起做」。

- V1 恢复 C 端宠友圈核心社区能力：动态发布/删除、发现与热门流、关注流、动态详情、评论、点赞、收藏、关注、举报、话题与运营审核。
- 首页「宠友圈热门」必须接真实社区热门流，不再显示「即将上线」占位。
- 此前 62 号契约、设计登记表 §4.4/§4.11 中「COM-001 未启动、社区一行不做」的表述，仅作为历史切片说明，不再作为实现边界。
- 仍不做：私信 IM、直播、AI 客服、黑名单完整能力、视频上传/转码、社区积分任务（`COMMUNITY_POST` 继续 `NOT_OPEN`）。
- 执行 CCR-COM-001 与 73 号契约。

## 二、首页内容位

用户裁决：「热门服务手动配置方便后面商家竞价」。

- 新增运营内容位模型 `marketing_home_block`，由运营手动配置首页三块：热门服务、宠友圈热门容器、植物&异宠。
- 预留 `sponsor_merchant_id` / `sponsor_store_id`；V1 不做竞价出价、扣费和结算，后续竞价只扩展投放与结算，不改变首页读协议。
- 图片走后台上传素材；标题、文案、图片、目标、排序、上下线均不需要小程序发版。执行 CCR-MKT-003。

## 三、验收口径

- 首页三块视觉按 Figma 首页 690:1550 / 690:3222 / 690:3601 的内容区实现；数据来自后台，前端只保留白名单版式与设计系统静态资产。
- 社区真实数据为空时，热门内容区失败关闭隐藏，不伪造帖子。
- 社区/首页内容位写操作均满足 requestId 幂等、运营权限与审计要求。
