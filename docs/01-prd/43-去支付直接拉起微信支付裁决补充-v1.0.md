# 43-去支付直接拉起微信支付裁决补充 v1.0

状态：产品规则批准（2026-11-27 用户裁决）。本文件是裁决记录与验收定义，不代表已上线。

## 1. 背景与来源

用户 2026-11-27 先对照设计稿 Figma 690:4837《确认支付》要求把「确认支付」整页改成半屏；看到半屏效果后随即改判：

> 「就是这里点击去支付 然后跳转到确认支付，这里能不能改为 后端创建订单，然后直接拉起微信原生支付信息，而不需要确认支付这一步 也就是图片中的那一步是不需要的」

## 2. 裁决

- **去掉确认支付这一步**：预约成功后回执里的「去支付」与订单详情里的「去支付」，单击即由小程序建支付单（`POST /api/v1/c/orders/{orderId}/payments`，HTTP 契约 10 §3.6）并调起微信原生支付，不再出现确认支付页或半屏。
- **支付窗口结束后的去向**（用户在「直接跳订单详情 / 留在当前页面提示」中选了前者）：微信支付窗口一结束就去订单详情，由订单详情显示服务端状态；刚付完的短时间内可能仍显示「待支付」，等微信回调到达后更新。
- **Figma 690:4837《确认支付》不实现**（设计源登记表 §4.29）：原稿里的「微信支付 / 支付宝」选择在小程序中本就不成立（HTTP 契约 10：C 端小程序 V1.0 不展示支付方式选择）。
- **订单详情读侧不新增字段**：同日早些时候为半屏摘要卡准备的 `storeName` / `serviceName` 随半屏一并撤回，契约与 OpenAPI 不变。
- 支付流程硬规则不变：拉起支付必须由用户点击触发；绝不本地虚构「已支付」态；取消、失败、未登录、发起失败都留在当前页并提示，「去支付」可再次点击；上次发起结果尚未确认时沿用同一请求编号，不重复发起。

## 3. 执行位置

- 小程序：`frontend-miniapp/src/consumer/booking/pay-launch.ts`（提示文案与失败归类）、`booking/use-pay-launch.ts`（调起流程）；入口 `components/booking-sheet/booking-sheet.tsx`、`pages/orders/detail.tsx`；兜底页 `pages/booking/pay.tsx`（直连 / 深链接用，同样单击即拉起）。
- 后端：无变化。

## 4. 验收要求

1. 预约成功后在回执里点「去支付」，直接弹出微信支付，中间没有确认页或半屏。
2. 订单详情里对未支付单点「去支付」，同样直接弹出微信支付。
3. 在微信支付窗口里取消或支付失败：留在当前页面并看到提示，按钮仍可再次点击。
4. 支付窗口正常结束后：从预约回执进入的，跳到订单详情；从订单详情进入的，留在订单详情并刷新。页面任何地方都不出现本地推断的「已支付」。
5. 未登录时点「去支付」：提示并引导登录，不发起支付。
