# 32-售后资金出路与未建页面裁决补充 v1.0

裁决日期：2026-10-13。裁决人：产品负责人。本文件为 SSOT 的实施裁决补充；与既有草案/讨论冲突处，以本文件为准。

## 一、售后退款资金出路（落定 OD-W0-001 的 V1 范围）

- V1 售后裁决产生的退款（全额/部分）一律走**微信支付原路退回**。
- V1 **不做**资金冻结/分账/提现/保证金；商家侧不设平台内资金账户。
- 影响面：admin 售后 decisions 的 FULL_REFUND / PARTIAL_REFUND 分支解除 fail-closed（现 503 公开不可用），退款执行按原路退回语义接入既有退款渠道执行链（submit / channel-query 任务族），不做分账即无分润。
- 执行约束不变：requestId 幂等、渠道回执确认、错误码登记；DisplayOrderStatus 仍由 order 统一计算。

## 二、未建页面批次（七页全做）

签到、拉新任务、积分商城、收藏、浏览足迹、地址管理、成为服务者——**七页全部进入实施**。附加规则：

1. **积分在 V1 维持只赚取/扣回、不消费**：积分商城页面按设计稿实现为**展示态**——商品可陈列，兑换动作不可用（不产生任何积分扣减），页面文案明示暂未开放。本条不放宽既有积分硬规则。
2. **签到与拉新的积分发放量必须支持后台配置**（运营侧配置项）；其余规则按常规签到/拉新语义执行——涉及产品规则的具体细则（如防重复口径、拉新成立条件）由各切片 CCR 定稿，需裁决处回禀，不自创。
3. 各页契约缺失走 CCR 流程；持久层遵守 MyBatis 统一裁决；写操作 requestId 幂等照旧。

## 三、发版节奏

暂缓上架准备：当前阶段继续补齐功能与验收，不启动真机全链路回归与提审材料。
