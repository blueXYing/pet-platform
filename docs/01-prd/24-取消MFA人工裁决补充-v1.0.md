# V1 取消额外MFA：人工裁决补充

状态：人工已批准。来源：用户针对AUTH-001 D1明确要求“后续如果说有这个认证则给取消掉”。本文件为原PRD的增量裁决，不重写原Word历史文件。

## 生效范围

V1取消额外多因素认证（MFA）能力和强制条件，涵盖运营登录、高权限/敏感操作及AUTH草案拟增加的第二因素认证。不得要求安装认证器或在已完成普通登录后再提供第二因素证明；不保留MFA配置、绑定、丢失恢复、challenge或升级认证入口作为本期功能。

- 运营编辑、审核员、运营管理员、财务、审计和超管均不因缺少MFA证明被阻止登录或执行已获权动作。
- 不增加`requiresMfa`、`mfaVerified`等作为授权事实或接口前置条件；AUTH草案相应路径、DTO字段、响应状态、例子及Provider待办须同步移除。
- 角色、动作、数据范围、账号状态和服务端最终授权检查仍执行；取消MFA不授予额外业务权限。

## 未被取消的独立规则

普通账号密码登录、短信作为原有主登录方式、C端微信登录的手机号校验/绑定和密码找回证明保持各自原规则。图形验证码/限流、会话超时及互斥登录、原因/用途、单人业务二次确认、脱敏和审计不因本裁决取消。普通短信流程不能换名成为已登录后的第二因素门禁。

本裁决仅处理MFA。AUTH D1的其它技术参数与D2最终授权时点仍待相应审阅，不因本次去除MFA自动批准。签约OD-W0-002和冻结写动作等未决项独立保留。

## 覆盖关系

SSOT新增“二十五、V1取消额外MFA”是当前上位规则。本补充覆盖原运营Word中的MFA要求、AUTH-001草案中的MFA设计和测试矩阵FLT-020中“MFA条件”部分；原Word与已提交草案保留历史，执行时不得再以旧条款增加MFA。

## 验收要求

1. 有效普通登录且角色/动作/范围允许时，不因没有MFA而拒绝高权限动作。
2. 无登录、未授权、账号无效或范围越界仍拒绝；没有业务状态变化并按规则审计。
3. AUTH草案/后续UI和API没有本期MFA第二步、challenge、因素绑定/恢复及依赖其证明的权限字段。
4. 原登录/手机号/重置证明及业务二次确认仍按来源执行，不能借此次删除验证和审计。

这是验收定义及产品裁决记录，尚未执行真实认证测试，不声明已实现登录或高权限业务。
