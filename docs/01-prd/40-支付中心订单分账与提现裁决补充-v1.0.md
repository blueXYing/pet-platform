## 1. 渠道与资金模型

1. 支付渠道仍为拉卡拉聚合主扫，小程序直接微信支付，不展示渠道选择（SSOT 第 14～15 行不变）。
2. **平台为唯一收单商户**。所有交易以分账标识（预下单 `settle_type=1`）进入平台商户的待分账资金。
3. 每个商家在拉卡拉开通为**分账接收方**，并与平台商户绑定分账关系。
4. **只使用订单分账**（拉卡拉交易分账 `/api/v3/sacs/separate`）。不使用余额分账、不使用可用余额定向转账。

## 2. 商家份额

1. 商家份额 = 分账基数 × (1 − 商家对外手续费率)，结果按分向下取整。
2. **商家对外手续费率**在运营后台按商家配置，默认 0.6%，以百分比保存 4 位小数；在**支付成功时快照**到结算单。
3. 拉卡拉实际收取的交易手续费由平台承担。对外费率与实际费率的差额即平台收入，无需单独配置；对账记录实际费率。
4. 平台**不另收佣金**。
5. 系统内部按金额计算后以固定金额模式（`calType=0`）提交分账，业务口径仍为"按比例"。

## 3. 优惠券

1. **平台券由平台出资**。分账基数按**使用平台券之前的价格**计算。
2. 订单分账只能分出本笔交易可分账金额。平台券导致商家份额超过可分账金额时：
   - 本笔交易最多分出：可分账金额 − 平台最低分得比例 × 交易金额（最低比例即委托书/1284 的"最低分账比例"，部署配置）；
   - 差额记为**平台应补**，进入运营后台"平台补贴应付报表"（按商家、按周期汇总），在系统外结算；
   - 系统不提供把差额标记为"已打款/已到账"的动作（22 号）。
3. 商家钱包是否展示"平台补贴待结算"：**待定**，默认仅运营后台可见。
4. **预留商家券**：结算单分别记录平台补贴金额与商家出资优惠金额；商家出资的优惠从分账基数中扣除。
   V1 券模板无出资方字段，现有券全部按平台券处理；以后增加出资方字段时不改结算口径。

## 4. 分账接收方开通

1. 平台商户开通分账业务（拉卡拉 1284，需分账结算授权委托书）由产品负责人在拉卡拉侧一次性办理，不在系统内实现。
   委托书勾选"按订单清分结算""指令清分结算"；"本商户最低需分得"比例影响平台券差额，见 §3 第 2 条。
2. 商家接收方的创建、变更、绑定关系（1287/1288/1290）通过拉卡拉接口进行，**由运营在后台代填资料**：
   - 收款账户、证件信息、身份证/银行卡照片、分账合作协议附件；
   - 敏感字段加密存储、展示脱敏，附件走私有素材存储；运营查看与提交须 RBAC 授权并审计。
3. 接收方未处于"已生效"状态时，到期结算单暂停，不跳过、不改分给他人。

## 5. T+d 与提现

1. **T = 核销完成时间**。核销完成后开始计时，到期（T + d 天）才发起订单分账。
2. **d 在运营后台按商家配置**：默认 7，范围 7～30（下限对齐核销后 7 天售后窗口，SSOT 第 364、371 行）；在核销时快照，改配置只影响尚未核销的订单。
3. 订单存在进行中的退款或售后时，结算单暂停，结束后按已退款金额重算再继续。
4. 接收方提款模式设为**主动提款**（创建接收方时 `settleType=01`），不允许自动结算提走。
5. 商家在小程序商家端**手动提现**，仅限商家 OWNER，写审计；V1 不增加短信验证码。
   可提现余额以拉卡拉接收方账户余额查询为准。

## 6. 分账后退款

1. 分账前退款：沿用既有原路退款，结算单作废或按比例减额。
2. 分账后退款（SSOT 允许核销后的合法普通退款与售后退款）：先发起分账回退（拉卡拉支持 180 天内），
   回退金额 = 退款额对应的商家份额；**回退成功后才执行原路退款**。
3. 回退失败（如商家已提现、余额不足）：退款暂停，转运营人工处理并告警；平台不垫付。

## 7. 前端范围

运营网页：商家结算配置（d、对外费率）、接收方开通与台账、结算单/分账/提现台账、平台补贴应付报表、异常处理。
小程序商家端：结算账户状态（只读）、钱包（可提现余额、待结算、明细）、提现与提现记录。

## 8. 不做

平台自建资金冻结、保证金、余额分账、定向转账、商家自助填写收款资料、短信验证码提现、
系统内标记线下打款到账、AI 客服等 V1 已排除能力。
