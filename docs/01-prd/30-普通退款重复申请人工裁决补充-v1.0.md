# 普通退款重复申请人工裁决补充 v1.0

状态：人工已批准，2026-09-30。依据 SSOT §38；补充三端最终 PRD 中未明确的退款申请轮次，原 Word 文件保持不变。

## 原始问题与回执

问题：商家拒绝退款后，用户能否再次申请普通退款？SSOT 只规定“一单最多一次实际退款”，没有限制申请次数。推荐允许再次申请，每次重新计24小时，但同一订单同时仅保留一笔待处理申请；已经创建退款单后禁止再申请。

用户选择：**“允许再次申请，按上述规则处理（推荐）”。**

## 已批准规则

1. 商家拒绝后，用户可以再次发起普通退款申请；不把“一次实际退款”扩大为“一次申请”。
2. 每次真正的新申请，重新计算商家24小时处理期限。
3. 同一订单同时仅有一笔待处理退款申请。网络重试、重复点击不是新一轮，不能重置原期限。
4. `refund_order` 创建后禁止再申请。退款渠道重试继续使用原业务退款单，不增加第二张业务退款单。

## 既定规则与边界

- 商家普通退款处理仍只有同意全额退款或拒绝；拒绝原因展示买家。部分退款仅运营售后裁决。
- `PENDING_MERCHANT` 申请本身不阻止核销。等待期间核销成功，不否决该普通申请的商家同意/24小时自动全额退款；与“旧未履约售后工单被核销失效”分开处理。
- 售后窗口按原 SSOT §6/§7，不能推导普通退款也有核销后7天截止。本次未新增普通退款期限或频次上限。
- 本次未决定售后“同一问题”识别、不同问题并行工单或员工绑定方式；这些不随普通退款申请轮次自动获得批准。
- 本文件仅同步用户已确认的产品规则。具体幂等、存储、来源证明和任务协议见[退款接续CCR](../../planning/ccr/CCR-W2-API-001/refund-application-proposal.md)，技术增量仍按相应审阅门禁推进。
- 不授权PR合并、生产迁移或生产启用；不宣称 REF-002/REF-004 已完成。
