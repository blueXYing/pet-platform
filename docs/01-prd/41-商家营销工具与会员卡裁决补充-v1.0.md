本补充覆盖 [38 号裁决补充](38-营销活动中心裁决补充-v1.0.md) §3 与 [71 号契约](../04-api/71-Marketing-Center-Contract-v0.1.md) §8 中「秒杀/拼团/裂变/会员卡」「商家自主发券」的排除项，以及 [SSOT §19](../00-ssot/01-SSOT-宠物平台V1.0-最终业务基线.md) 中「只做单次服务、不做次卡」与本补充相关的部分；其余交易、退款、售后、核销、排期、积分硬规则全部不变。

> 执行约定：执行智能体以本补充为产品决策来源，不得再向用户确认本补充已写明的事项。未被本补充覆盖的冲突，按「SSOT > 最终 PRD > 技术基线 > Schema/API/Event/Scheduler > Test」处理；确实无法消解的，停止并报告，不得自行改规则。

## 1. 范围与分期

| 阶段 | 能力 | 说明 |
|---|---|---|
| P1 | 营销工具 hub、节日营销/商家自建活动、商家封面素材 | 保留平台活动报名；商家创建后仍由运营审核发布 |
| P2 | 限时秒杀（服务限时价格） | 仍为单次服务、必须预约；不新增订单类型 |
| P3 | 商家自建优惠券 | 仅无门槛券/满减券；商家出资；运营审核 |
| P4a | 裂变拉新（返券） | 邀请绑定 + 双方商家券奖励；不做现金返现 |
| P4b | 裂变拉新（返现） | 依赖支付中心钱包/提现；另立 CCR |
| P5 | 会员卡：储值卡/次卡/年卡 | 独立资金域；依赖支付中心阶段 2–6 与法务/财务确认 |
| 不做 | 赠品活动、拼团、买一送一、直播、AI 客服、私信 IM、积分消费 | 维持既有排除 |

## 2. 通用规则

1. 商家活动、商家券、秒杀、会员卡产品/充值/退款均须运营审核或平台资金规则约束；**商家不可直接发布**。Figma 的「立即上架」一律改为「提交审核」。
2. 商家不得修改订单、支付、退款、售后、核销、排期状态机；营销/会员卡只能通过既有事件与 `*-api` 协作。
3. 所有写操作：`X-Request-Id` 幂等、乐观 `version`、append-only 审计；资金类动作必须记录金额/次数/前后值。
4. 统计只展示可证明事实；曝光/点击/成交归因在 P6 之前不得展示（71 号 §8 仍有效）。
5. 不允许展示无法兑现的优惠、余额、返现或套餐；未实现的工具入口显示「筹备中/暂不开放」。
6. 商家端资金/发卡/退款动作仅 OWNER；员工无资金权限；运营按 SSOT §24 单运营 + 数据范围，失败关闭。

## 3. P1：商家自建活动（节日营销）

### 3.1 字段

| 字段 | 规则 |
|---|---|
| 活动名称 `name/title` | 前端一个输入，后端两字段同值；2–100 字 |
| 封面 `coverAssetId` | 商家通过营销素材端点上传；草稿可空，提交审核前必填；仅本人/本店 ACTIVE 素材 |
| 节日主题 `themeCode` | 必填；`SPRING_FESTIVAL/MID_AUTUMN/NATIONAL_DAY/CHRISTMAS/NEW_YEAR/DOUBLE_11/OTHER` |
| 玩法 `playType` | P1 仅 `THEME`（主题活动）；P2 增 `FLASH_PRICE`，P3 增 `MERCHANT_COUPON`，P4 增 `REFERRAL`；其他值 400 |
| 主打项目 `highlightText` | 可选，≤100 字；纯文本，不得暗示未配置的折扣/赠品 |
| 活动说明 `description` | 可选，≤300 字（码点） |
| 有效期 `startAt/endAt` | 必填，`startAt < endAt`；ISO-8601 UTC，前端按北京时间选择 |
| 优惠力度 | P1 不采集；没有真实价格/券规则时禁止展示 |

### 3.2 审核与状态

`DRAFT → PENDING_REVIEW（商家提交）→ SCHEDULED/ONLINE（运营发布）`；`PENDING_REVIEW → REJECTED`；`DRAFT/REJECTED/PENDING_REVIEW → CANCELED`。商家可编辑 `DRAFT/REJECTED`；提交后不可编辑；运营驳回原因 1–500 字。状态机沿用 71 号 §2.1。

### 3.3 入口与保留能力

- 营销工具 hub 展示 6 个工具卡：优惠券、会员卡、限时秒杀、裂变拉新、赠品活动、节日营销。
- P1 仅「节日营销」可用；其余显示「筹备中」/「暂不开放」，不可进入空壳表单。
- 保留「平台活动报名 / 我的报名」，独立入口，不删除、不弱化。
- 统计只展示：活动总数、进行中数、待审核数、已报名平台活动数；不展示订单/营收/转化率。

### 3.4 设计偏差登记

- Figma「立即上架」→「提交审核」。
- Figma「节日套餐/买赠有礼/抽奖活动」→ 不展示；「限时折扣/满减优惠」分别在 P2/P3 接入后才展示。
- Figma「优惠力度（元）」P1 不采集。
- Figma「带来订单/营收」P1 不展示。

## 4. P2：限时秒杀

1. 秒杀是**服务项目的限时价格**，不是新订单类型、不是新服务形态；仍必须预约、单次服务。
2. 商家创建 → 运营审核 → 窗口生效；同一服务同一时间最多一个有效秒杀窗口。
3. 秒杀价 >0 且 < 服务划线价/日常价；支持可选发放总量、每人限领。
4. 下单事务内预占名额；支付成功消费；取消/超时释放；已支付订单退款不恢复名额。
5. 优惠叠加：秒杀价为基准，券在秒杀价后计算；折后应付必须 >0（61 号）。每单最多一张券（P3 不做平台券+商家券叠加）。
6. 分账基数 = 服务原价 − 秒杀优惠 − 商家券优惠；平台券不扣商家。支付中心 §5「商家出资优惠 V1 为 0」在本阶段放开。
7. 商家不得直接发布；Figma「立即上架」改为「提交审核」。

## 5. P3：商家自建优惠券

1. 仅无门槛券/满减券；不得折扣券、兑换券、券包。
2. 商家出资；平台券由平台出资。**本阶段不做平台券+商家券叠加**：每单最多一张券，订单快照记录 `fundingType`。后续要叠加另立 CCR。
3. 商家创建券模板/券活动 → 运营审核 → 发布；商家不得向指定用户发券，只能配置公开领取。
4. 预算/总量/每人限领/有效期由商家设置；预算不足停止领取，不超发；预算账本与券台账分离。
5. 领取/使用/退款返券沿用 61/72；全额退款返券、部分退款不返券。
6. 结算：商家券面额从商家分账基数扣除；退款按支付中心 §5 重算/回退；日对账逐笔核对。
7. 统计可展示：发券数、领取数、核销率、带动订单数（券实例关联订单去重）、净 GMV（需定义退款口径）；不展示曝光/点击。
8. 支付中心阶段 2（结算/分账）未交付前，P3 不得上线；只能开发到默认关闭的草稿状态。

## 6. P4：裂变拉新

### 6.1 P4a（本轮定义）

1. 奖励类型固定为**商家券**（P3 模板/活动），不做现金、不做积分（积分可作为后续扩展，避免平台出资争议）。
2. 双方奖励：被邀请人绑定后获得一张新客券（用于首单）；邀请人在被邀请人首笔订单**核销完成且 7 天内无退款/售后**后获得一张商家券。
3. 资格：被邀请人必须是该商家新客（无已支付订单）；每人终身只能绑定一个商家邀请关系；禁止自邀；每邀请人月度奖励上限由活动配置；总预算/总量封顶。
4. 绑定唯一：`(programId, inviteeUserId)` 唯一；`(programId, inviterUserId, inviteeUserId)` 唯一。
5. 退款/撤单：奖励发放前退款 → 不发；发放后发生退款 → 按活动规则撤销未使用券，已使用券不追回（记录损失），不产生现金追偿。
6. 活动需运营审核；商家不可直接发布；统计展示邀请人数、新增客户、奖励券支出，不展示现金。

### 6.2 P4b（阻塞）

现金返现、拼团不做；返现依赖支付中心钱包/提现/结算阶段 5+，另立 CCR 与裁决。Figma「返现/拼团」在 P4a 页面显示为「返券」，拼团入口不展示。

## 7. P5：会员卡（储值/次卡/年卡）

### 7.1 资金与合规

1. 卡产品、开卡、充值、消费、退款、过期、闭店处理均需 41 号本补充 + 法务/财务书面确认；未确认前不得开启生产开关。
2. 推荐资金模型：**平台代收充值款，按实际消费/核销结算给商家**；支付中心阶段 2–6 提供结算、分账、回退、钱包、提现、对账。
3. **禁止商家在「添加会员信息」里直接填写可用余额**。余额只能来自支付成功的充值单；线下现金收款若要做，另立「线下收款登记/对账」裁决，不得混入卡余额。
4. 充值/退款走 `PaymentCenterApi` 的 `bizType=MEMBER_RECHARGE`；不得使用 0 元微信单或绕过支付通道。

### 7.2 卡类型

| 类型 | 购买 | 使用 | 退款/过期 |
|---|---|---|---|
| 储值卡 | C 端微信支付充值；可配置赠送金额 | 下单余额支付，可部分使用；余额不足不可支付 | 未消费实付余额可退；赠送金额不退；过期规则由产品配置并在购买页展示 |
| 次卡 | C 端支付购买 N 次 | 下单/核销扣 1 次；退款回补未使用次数 | 未使用次数按 `实付/总次数×剩余次数` 向下取整退款；已使用不退 |
| 年卡 | C 端支付购买有效期 | 有效期内预约；可配置总次数/每月公平使用上限 | 激活后不退；未激活可退；过期作废（购买页明示） |

### 7.3 账本与订单

1. `member_card_ledger` append-only：`RECHARGE/CONSUME/REFUND/ADJUST/EXPIRE/REVERSE`；余额/次数不得为负；`request_id` 唯一。
2. 储值卡：下单事务预占余额 → 内部支付成功扣减；取消/超时释放；退款回余额。
3. 次卡：下单预占 1 次 → 支付成功扣次；取消/超时释放；退款回补；核销只记录使用事实，不重复扣次。
4. 年卡：下单校验有效期/次数上限；订单内部支付；核销记录使用；退款规则见 §7.2。
5. 订单新增支付方式 `MEMBER_BALANCE/MEMBER_COUNT/MEMBER_YEAR`；不创建微信支付单；订单状态由内部支付事件推进。修订 38/11/40/41/49/50 号契约，禁止 0 元微信单。
6. 分账/退款：充值款按消费/核销结算；卡支付订单退款回卡/余额；已消费部分不退；日终对账。

### 7.4 权限与隐私

- 商家端仅 OWNER 可开卡、充值确认、退款申请、查看资金面；员工不可见。
- 手机号脱敏；宠物信息遵守 69 号客户档案隐私红线；不得导出、批量触达。
- 运营调整余额/次数必须审计，记录原因、操作者、requestId；单运营无第二人复核，但必须留痕。
