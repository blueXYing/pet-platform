# 支付发起与到期协调 v0.1

2026-09-28，用户批准[四项推荐方案](../../planning/ccr/CCR-W2-API-001/payment-dispatch-expiry-proposal.md)。本契约补充 23、39、40 号，采用 SQL41；实现默认关闭，不授权 PR 合并、生产迁移或真实渠道交易。

## 1. 发起与身份

内部 `PaymentInitiationApi.create(PreparePaymentCommand)` 先走原 `PaymentPreparationApi` 的请求绑定，再处理一次原付款号派发。成功必须返回真实已验签且仍有效的微信参数；没有参数不得以 202 或“受理成功”替代。无公开消费者 HTTP。每订单仍只有一条付款记录，重试不改变 paymentNo、金额、商户或原十分钟截止。

`PaymentIdentityApi.requireCurrentPaymentIdentity(userId,appId,storeId,context)` 由 USER Owner 提供。在同 DataSource/店 guard 事务内，要求可信 USER 与目标用户相同、当前账号 ACTIVE，精确读取该 AppID 下唯一 WECHAT_MINI 绑定；缺失、多绑定、错误类型、非法字段或依赖故障都拒绝。openid 不由客户端指定、不直接跨模块查表、不进入日志/事件。SYSTEM 查单使用原支付绑定，不要求用户仍在线。

首次预下单前重新校验 ORDER 可支付、USER 当前身份和支付归属，将身份受保护等值摘要、原渠道请求时间/日期、原期限和“可能已发送”事实同事务提交。然后离开数据库事务和店锁请求渠道。历史付款记录没有 SQL41 派发事实时，不推定从未发送，不回填猜测。

## 2. 短期参数

剩余时间按原付款截止计算，`timeout_express` 使用整分钟；不足一分钟不再发起新的预下单，已经取得且仍有效的参数可继续使用。预下单参数本地有效期不超过原付款截止，也不因响应延迟或重试重新起算。渠道参数计时起点须在正式联调核实，本地拒绝返回不代表渠道已经关单。

仅加密保存最小微信参数，AES-GCM 密钥由部署配置提供、不内置默认密钥，AAD 绑定付款身份。长期请求绑定不保存明文参数。每次返回前重新验证当前用户、订单归属与可支付性、首次微信身份等值、原付款期限、参数有效期及未被到期阻断。身份改变、密文损坏、参数丢失或失效不得返回旧参数。

一旦持久记录“可能已发送”，后续不能重新预下单，除非未来已单独验证渠道同号重提能力。当前实现不提供该能力；未知结果只查原号。没有第二付款号、自动换 requestId 或自动延长期限。DB 提交结果不明也只能读取原绑定/状态恢复；不能再次发送来猜测结果。

## 3. 渠道适配与结果

仅 PAYMENT 基础设施使用固定拉卡拉 SIT/生产 HTTPS 地址。精确发送已签名的原始字节；普通响应先验签再解析，签名头必须唯一。禁止重定向；连接与完整响应均有有限超时，正文上限 64KiB。网络、HTTP、签名或协议异常保留 UNKNOWN，无应用层自动重试。JDK 客户端需要启动时关闭连接重试，不能靠运行中改属性假装满足门槛。

查单必须使用首次请求对应的渠道交易日期，不能跨午夜换成当天。`BBS00000` 只表示查到；状态 SUCCESS 才是候选成功。查询成功通过包内受信渠道适配器交给原 PAYMENT 成功写入器，核对商户、原号、金额、钱包、流水、实付及时间，并在同店 guard/同事务保存来源 QUERY、原响应 SHA-256、去重摘要、PAID 与唯一成功事件。通知与查询竞争只产生一次成功事件；退款/撤销先到仍保留 RECONCILIATION_REQUIRED。外部 SYSTEM DTO 不是成功证明。

## 4. 到期协议

原预约到期任务及 generation 不变。ORDER 先在短事务验证当前订单、预约和原截止确实到期，再在事务外调用 `PaymentExpiryCoordinationApi.reconcileForExpiry`。SYSTEM 请求键固定 `PAYMENT_EXPIRY_ORDER:{orderId}:0`；命令必须核对原订单/店/期限，重试不改变目标。

协调先持久阻断新发起。完全没有派发的记录可以原子转为 FENCED_UNSENT。已发送则使用原号查单，必要时关单，再查最终状态；ACK、超时、FAIL、not-found、UNKNOWN 或租约失效均不能代替安全释放证明。尚未解决的预下单发送不能因一次 CLOSE 查询而变成可释放。

TERMINAL_CLOSED 需要原预下单已验签响应、已验签关单受理、独立已验签 CLOSE 查询及持久的终局能力确认。本轮能力开关默认 false；正式渠道终局保证未核实则保持占用，不能将测试替身的保证当真实渠道事实。

ORDER 最终关闭事务内调用 `BookingPaymentExposureApi.requireSafeToExpire`，再次读取同库当前付款和派发事实，核对原期限、FENCED_UNSENT 或完整终局证明，排除成功/实付、退款撤销、孤立流水或来源不明数据。协调命令返回值不是离线许可。订单取消、SCH 到期及审计仍同事务提交，COUPON 当前保护继续执行。

成功结果先到则保留占用等待 ORDER 正常确认；关闭先完成后再到的真实 SUCCESS，仍按 40 号记录 CANCELED/PAID、保持 SCH EXPIRED 并产生一次迟到退款意图。迟到退款执行、自动接单及券链路不因本契约自动交付。

## 5. 验收与启用

必须覆盖原号只发一次、失败绑定、并发/提交 ACK 丢失、短期密文与身份变更、最后不足一分钟、跨午夜查单、未发起阻断、在途/未知/仅关单 ACK 不释放、终局证明与回调竞争、查询/通知唯一事件、旧记录保护和架构边界。

缺正式商户、证书、微信关联、加密密钥或经确认的渠道时区时失败关闭。真实支付验收、最终关闭语义与营销实付映射仍依赖正式联调；不以本地服务器/测试密钥验收代替。
