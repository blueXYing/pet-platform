## 1. 公共 ID

- 主键/订单号/退款单号沿用Snowflake BIGINT，内部Java Long；所有跨模块API、HTTP/JSON/TypeScript ID使用String，不能先转JS Number。
- 有效词法为ASCII正整数，无前导零、符号、空白、小数或指数；范围1～9223372036854775807。`9007199254740993`与最大值必须精确往返。验证码、traceId、渠道码不是Snowflake业务ID，不套此类型。
- `SnowflakeIdGenerator.nextId(): long`只有生产接口，没有S1生产提供器；`PublicIdCodec`由`DecimalPublicIdCodec`作纯转换，不证明ID存在、归属或唯一发号。
- 已接受的生产方向：正64位1/41/10/12，epoch=2026-01-01T00:00:00Z，worker 0～1023，同毫秒4096序列，耗尽等待下一物理毫秒，有界等待建议1秒后失败；回拨/worker所有权不安全则停止，不降级UUID或自动换worker。具体独占、高水位持久存储/fencing/预留窗口仍未定，不能把静态worker配置当生产唯一性证明。

## 2. 时间与金额

采用`java.time.Clock`注入，不增加TaskClock；业务时区统一配置，已接受初始建议Asia/Shanghai。内部Instant/OffsetDateTime，API ISO-8601带偏移，持久DATETIME(3)建议UTC解释；历史DB存量必须先核对，不能直接改时区重解释。Clock墙钟不用于elapsed预算。Scheduler/SQL13的claim/lease继续以同库NOW(3)为权威，fixed Clock不证明真实DB租约安全。

无偏移/非法日期拒绝；外部写入非零亚毫秒拒绝，不截断/舍入。`.123000000`表示整毫秒可以接受，`.123000001`拒绝。基础检查保留原OffsetDateTime与Instant，不替代预约分钟规则或业务截止比较；规范摘要等值化再按§4转UTC。

Money使用BigDecimal/DECIMAL(18,2)，绝对值最大9999999999999999.99，不用float/double资金运算。

- `MoneyCodec.parse(String)`接受可选负号、无冗余前导零的整数，可无小数点或带1～2位小数；128/128.0/128.00都变成scale 2的128.00。拒绝128.、128.000、指数、正号、空白、JSON number、超范围、负零词法及非ASCII数字。
- `format(BigDecimal)`输出两位定点String，补零或去掉无意义尾零必须数值完全相等，禁止舍入。BigDecimal("128.000")→128.00、BigDecimal("1E+2")→100.00；128.001拒绝。BigDecimal已不保留原负零词法，因此format不能检测原始输入负零，parse负责该拒绝。
- 公共Codec允许负数/零不赋予业务资格。OpenAPI现有订单/退款字段沿用非负金额schema；是否必须正数、退款不大于实付仍依原业务。比例(10,6)、体重/评分不走MoneyCodec，不引入业务舍入/优惠规则。

## 3. CommandContext 与请求键

CommandContext仍只有`requestId/traceId/operatorType/operatorId/source`五字段，OperatorType=USER/MERCHANT_STAFF/PLATFORM_OPERATOR/SYSTEM。不新增tenantId、workspace、权限DTO或新身份体系。

所有写命令requestId必填；基础校验拒绝null/全空白、控制字符、无效Unicode及超过512 UTF-8字节，不trim、不改大小写。终端X-Request-Id另要求完整8-4-4-4-12 ASCII十六进制UUID，不限定新版本、不接受UUID.fromString的短分组；内部任务/回调/事件确定性串不强制UUID。终端重试保留原UUID及业务参数，查询GET无此必填要求。

traceId缺失由原HTTP适配器生成并返回，不是幂等key。actor必须来自可信身份而非客户端operatorId/source/门店字段；非SYSTEM解析已认证主体，SYSTEM用稳定逻辑身份而非worker实例号；source只是技术来源。匿名/签约/真实RBAC映射仍由AUTH原Owner处理。S1 `PublicContractChecks`只检查requestId或时间值，**不生成trace、不认证、不证明授权**；Context record本身不自动执行HTTP校验。

## 4. 作用域与规范摘要

逻辑唯一元组：`(commandNamespace, actorType, actorId, authorityScope, requestId)`，全非空、固定域值替代NULL、严格字节比较。namespace为服务端稳定业务动词，普通DTO升级不换key域；scope仅承载已有授权的merchant/store或固定consumer/platform域。业务目标storeId同时入参数。不同主体/命令可用同requestId，但不因此能访问他人资源；客户端坐标不是真实scope证据。

认证及传输基础校验后，在可信scope查询原绑定，按绑定的canonical/schema版本作静态校验；新key才用当前schema。规范参数树包括所有影响写入的路径/查询/body字段、动作、目标、理由/用途、期望业务版本。排除requestId/traceId/Authorization/传输签名/重试次数/纯技术source；verificationCode/couponCode等敏感业务输入仍参与受保护等值比较。

canonical-v1：对象键按Unicode码点排序、UTF-8无BOM紧凑JSON且无尾换行；JSON标准转义、非ASCII原样，不转义可选斜线，拒绝重复键/未知字段/孤立surrogate。字符串不trim/大小写折叠/Unicode归一；数组保序，只有schema已定无序集合才排序；null与缺字段不同，明确默认值才可补默认。ID保持String；金额经无舍入规范化；时间按字段已定语义转UTC毫秒，偏移若有业务意义单列；其他数值按schema，不做通用浮点转换。

保存canonicalVersion、SHA-256标识、摘要及受保护规范字节作碰撞/等值复核，不只相信hash；加密随机IV不参与摘要。敏感材料最小化、加密和受限读取。规范参数/回执建议各64KiB上限；具体字段白名单由原Owner落实。绑定版本不可覆盖重算，不能通过新版本另建key绕过原事实；无法兼容拒绝并告警，后续兼容设计门禁不因此消失。

## 5. 事务、并发、失败与成功回执

默认采用独立DB绑定记录加原业务约束，记录与受保护业务使用同库、同事务管理器；业务表唯一键+模块结果适配器若能证明作用域/不可变参数/首次结果/失败绑定/原子性全部满足，可作合规替代，不强制所有命令统一物理表。Redis只能优化，不能成为唯一持久事实。

1. 当前认证/动作权/数据范围初检和静态规范化。未授权者不得获知绑定存在、摘要或旧回执。
2. Admission短独立事务唯一绑定RESERVED和原参数。必须没有已开始业务写的外层事务，不含hold/guard/Provider副作用。RESERVED仅表示绑定，不是RUNNING租约。
3. Execution锁该记录并当前读。未成功时再校验当前权限与业务资格，将本模块业务事实、首次成功最小回执、必要task/outbox意图同顶层本地commit，最终commit后才响应。回执序列化失败也回滚业务；禁止REQUIRES_NEW提前提交成功。
4. 同参已成功：每次重新校验当前身份、动作权、结果资源范围和敏感用途/脱敏，然后返回第一次成功业务回执；不再运行已消耗的一次性执行资格、不写第二次业务。资源最新状态另查询，旧actions不是当前授权；当前traceId可变化。
5. 同key异参：绑定存在即409 IDEMPOTENCY_KEY_CONFLICT，首次执行失败也不得覆盖原参数。业务拒绝/技术失败：执行事务整笔回滚，原绑定留存，同参可重新验证再试，不固定失败回执；新参数须明确新意图，不能对未知结果自动换UUID。
6. 同参争锁有界等待，接受的默认建议预算2秒。超时409 COMMON_CONFLICT，data:null，明确忙提示和原key稍后重试；不能将所有409或COMMON_CONFLICT当可自动重试。异参冲突不可当忙。胜者释放后新事务/当前读确认，避免旧快照。
7. commit ACK未知向权威主库查原key：SUCCEEDED重放，RESERVED取锁后可执行，锁仍占用按忙处理；DB/旧版本读取设施不可用503 COMMON_DEPENDENCY_UNAVAILABLE，不能凭网络错误新建key重做。死锁/连接错误须整笔回滚，有界原参数重试，不能提交半业务。

本地闭包不含Provider HTTP，不假定跨模块API全局回滚。不同requestId仍受业务唯一键、CAS、order guard及按来源的退款/核销规则；不把“当前未履约售后失效”扩为所有核销后退款禁止。同步API原能力不变，不统一改为异步。

## 6. 保留、安全与响应

V1不自动删除去重绑定与成功最小回执，RESERVED不因年龄成为新key；归档仍参与查重。不是全部敏感原文无限保留，也没有授权新的定时清理。确需清载荷须先保证最小回执兼容重放或明确审查限制，保留不可复用墓碑，不能先删后长期503冒充验收完成。

每次重放核当前授权，失效会话401、无权403或既有防枚举404，不带旧data；权限查询失败关闭。敏感结果按当前策略脱敏，不缓存令牌/完整渠道原包/密钥/临时导出能力/旧actions作未来授权。当前授权与执行资格分开；并发撤权授权快照规则仍等待AUTH落实。单运营、不新增第二人审批。

首次创建201、更新及幂等成功200，业务回执稳定而非字节级HTTP包；错误码使用现有12号登记，S1 Java纯组件只抛IllegalArgumentException等字段错误，不自行输出HTTP码。HTTP适配器后续映射COMMON_INVALID_ARGUMENT；S1不等真实API已执行此契约。

## 7. Provider、事件与任务

只有原Contract允许“可靠受理回执”的命令才能将本地受理视为SUCCEEDED。createPayment原成功必有wechatPayParameters，不能被“受理”替代/新增202，也不能无限重放过期支付参数。同步依赖Provider结果的命令必须原Owner完成意图持久化、未知查单、外部结果后本地成功、短期参数更新/失效与敏感返回映射；未获审查前禁止直接接入公共成功重放。

渠道超时不是FAILED，保持原paymentNo/refundNo查询，仅ChannelCapabilities已明确支持时原号重提；不创建第二张业务退款单。公共幂等不是渠道恰一次。迟到支付继续按SSOT保持关闭、真实渠道金额退款、不触发正常OrderPaid链路。

Event的(eventId,consumerName)消费日志与该消费者业务同事务；部分已成功消费者不重做。任务requestId按既有generation确定，attempt/worker变化不换key；task_key与公共Snowflake不同。S1不改事件载荷、Scheduler状态或lease规则，不启动PLAT-004。
