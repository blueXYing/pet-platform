# 可观测与日志基线补充 v0.1（草案，随PR合并生效）

> 本补充经用户2026-09-15授权由PLAT-005起草。多数条目为既有散落契约的收敛（HTTP10 §2.4/§1630敏感字段、Error12错误结构、task-core异常日志先例），新增仅为工程纪律，不含产品行为。

## 1. 链路标识（MDC）

- 每个入站HTTP请求由 `TraceContextFilter` 处理：`X-Trace-Id` 存在且合法（8~64位ASCII字母数字连字符下划线）则沿用，否则服务端生成UUID；始终通过响应头 `X-Trace-Id` 回显（HTTP10 §2.4）。
- `X-Request-Id` 为完整8-4-4-4-12 UUID时原样入MDC并回显；写入接口必填性由各命令适配层按HTTP10执行，过滤器不代行。
- MDC键：`traceId`、`requestId`；application.yml 日志格式串已预留，请求结束必须清理，禁止线程复用泄漏。
- 异步/后台组件（Worker、Outbox分发器）转发链路标识时以显式参数为准，不隐式读取调用方MDC。

## 2. 日志级别

| 级别 | 用途 |
|---|---|
| ERROR | 系统级故障需人工介入：依赖不可用、数据一致性告警、兜底500 |
| WARN | 业务拒绝、可重试失败、配置缺口（如无注册消费者） |
| INFO | 适配层请求边界（方法/路径/状态/耗时）、关键状态迁移 |
| DEBUG | 仅开发期细节，生产默认关闭 |

## 3. 内容红线

- `password/code/token/secret` 及等效凭证不进入普通日志（HTTP10 1630行既有规定）。
- 异常日志记异常类名与稳定错误码，不落原始SQL参数/业务载荷（task-core先例）。
- 交易、支付、退款、核销、审计事实禁物理删除（技术基线既有规定），日志不替代审计表。

## 4. 统一响应与异常

- 成功：`ApiResponse{code:"SUCCESS",message,data,traceId}`；错误：同形状 `data=null`，code取Error12稳定码（HTTP10 1630行）。
- 适配层不得再手写错误JSON；`GlobalApiExceptionHandler` 兜底全部未覆盖异常为 `COMMON_INTERNAL_ERROR`/500，不泄露堆栈细节。AdminAuth现有切片行为保留，后续由AUTH域统一收敛。
- 内部Java层错误事实用 `ApiError(code,message,traceId,details)`（Error12 §1），HTTP映射只属适配层。

## 5. 不属于本补充

日志采集/存储/检索/告警平台选型与接入、访问日志格式标准化（如JSON日志）、metrics/tracing协议——V1暂不做，留待运维阶段另行裁决。
