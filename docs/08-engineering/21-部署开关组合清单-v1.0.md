# 部署开关组合清单 v1.0

状态：已批准执行（用户 2026-10-08 裁决，E2E 发现 PRF-#133 / F-1）。本文档是 pet-boot 装配开关的**单点权威清单**：每个开关的用途、默认值、硬依赖（不满足则**启动失败**）、软依赖（对应能力运行时 503 失败关闭）、合法/非法组合与三档推荐组合。部署照单执行；新增或修改开关的切片必须同步更新本文档（Definition of Done 的一部分）。

依据：`backend/pet-boot/src/main/java/com/petplatform/boot/config/` 全部 `@ConditionalOnProperty`/`@ConditionalOnExpression` 装配类与 `adapter/web` 控制器条件注解（基线 origin/develop，含 PR#131/#132/#133/#134），以及 PR#133 `E2eCoreLoopServer`（`pet-boot` 测试源 `com/petplatform.boot.e2e`，已并入 develop）实测可启动的全量组合。

## 0. 三条隐藏底座依赖（先读）

开关之间的依赖不只是显式校验，以下三条是散落在装配代码里、最容易踩的隐式依赖：

1. **生产 Snowflake ID 提供器只有一个来源：`pet.auth.admin.enabled=true`**。`HutoolSnowflakeIdProvider`（`@ConditionalOnMissingBean(SnowflakeIdGenerator.class)`）定义在 `AdminAuthConfiguration`。任何需要 `SnowflakeIdGenerator` bean 的开关（`pet.auth.c`、`pet.outbox`、`pet.notification.delivery`、`pet.order.creation` 及全部含 worker 的域）在 `pet.auth.admin.enabled=false` 时要么装配失败、要么整体不生效（outbox/notification.delivery 的 `@ConditionalOnBean(SnowflakeIdGenerator)` 直接跳过装配）。**结论：当前代码形态下，admin auth 是事实上的全局底座。**
2. **`pet.schedule.protection.enabled` 提供跨域共享 guard/facts/proof bean**（`ScheduleCapacityGuardApi`、`ScheduleProtectionFactsApi`、`MerchantCurrentStaffFactsApi`、`OrderProtectionFactsApi`、`ScheduleCapacityProofApiImpl`）。下单、排期写、员工绑定、核销、退款、售后、自动确认全部注入这些 bean——关掉它，以上任何域开启都会因 bean 缺失启动失败。
3. **outbox / async_task / notification_delivery 等基础设施表必须先建**，对应装配不执行任何迁移。`pet.outbox.enabled=true`、`pet.notification.delivery.enabled=true` 及一切 `*.worker.enabled=true` 隐含"表已存在"这一前置。

## 2. 组合后果矩阵

### 2.1 已证实的启动失败组合（F-1 原案）

**`pet.outbox.enabled=true` + `pet.payment.foundation.enabled=true` + （`pet.order.merchant.enabled=true` 或 `pet.aftersale.enabled=true`）+ `pet.refund.late.enabled=false` → 启动失败。**

机理：`LateRefundConfiguration` 在 `payment.foundation && (refund.late || order.merchant || aftersale)` 时激活；只要激活就无条件创建 `LateRefundService`。`LateRefundService.eventTypes()` 在 `pet.refund.late.enabled=false` 时返回**空集合**；`OutboxDispatcher` 构造时把所有 `IntegrationEventConsumer` 注册进订阅表，遇空订阅抛 `IllegalArgumentException("Consumer needs a consumerName and at least one eventType")`，整个 Spring 启动失败。这就是 PRF-#133 记录的组合失败。

**合法边界**：
- outbox 开 + 三者（refund.late/order.merchant/aftersale）全关 → 合法（LateRefundConfiguration 整体不激活，无空订阅）。
- outbox 关 → 任意组合合法（Dispatcher 不存在，不注册消费者）。
- outbox 开 + refund.late 开 → 合法（订阅 `LatePaymentDetectedEvent` 非空）。
- 排查同类风险时注意：当前代码树中**只有 `LateRefundService` 一个消费者存在条件性空订阅**（其余消费者 `eventTypes()` 均为常量非空集合，2026-10-08 复核）。

**其余已证实/由 guard 直接断言的非法组合**（guard bean 启动期抛 `IllegalStateException`）：

| 非法组合 | 失败信息（装配类） |
|---|---|
| `auto-confirm.worker/repair=true` 而 `auto-confirm.enabled` 或 `payment.foundation` 关 | "Auto-confirm execution and repair require task production and payment foundation"（`OrderAutoConfirmTaskConfiguration`） |
| `auto-confirm.enabled=true` 而 `payment.foundation=false` | "Auto-confirm task production requires payment foundation" |
| `order.merchant.http/worker=true` 而 `order.merchant.enabled=false`；或 `order.merchant.enabled=true` 而 `payment.foundation=false`；或 `order.merchant.http=true` 而 worker/auto-confirm(+worker) 不齐 | "Merchant order flags require complete payment, command and worker dependencies"（`MerchantOrderConfiguration`） |
| `order.reschedule.enabled=true` 而四依赖不齐 | "Reschedule requires pet.xxx.enabled"（`OrderRescheduleConfiguration`） |
| `refund.application.(worker|http|enabled)` 依赖不齐 | "Refund application requires real session, merchant and payment dependencies"（`RefundApplicationConfiguration`） |
| `aftersale.*` 子开关（http/worker/refund）在 `aftersale.enabled=false` 时开启 | "Aftersale dependent switches require workflow"（`AfterSaleWorkflowConfiguration`） |

### 2.2 合法但需知后果的组合

- `outbox=true` 而各 `notifications-enabled=false`：事件在 outbox 积压（开启后补投），Dispatcher 空转合法。
- `notification.delivery=true` 而无真实微信适配器 bean：装配成功，投递任务失败关闭（`UnconfiguredWechatDeliveryAdapter`）。
- `order.expiry.enabled=true` 而 worker 关：过期命令可被调用，但无人自动执行（10 分钟占位不会自动关闭）。
- C 端 `/c/orders`、`/c/refund-applications` 等路由壳随 `auth.c` 存在，内核开关关闭时按契约 503，不半执行。

## 3. 三档推荐组合

### 档 ① 全量联调 / E2E（PR#133 E2eCoreLoopServer 实测可启动）

完整交易闭环（登录→浏览→下单→沙箱支付→接单→取码→核销→退款申请）。可直接对照 `pet-boot` 测试源 `com.petplatform.boot.e2e.E2eCoreLoopServer`（分支 codex/e2e-core-loop-20261007，PR#133）：

```
pet.auth.admin.enabled=true                # + 显式密钥/origin/Redis/审计路径;提供 Snowflake
pet.auth.c.enabled=true                    # + Redis + 微信 app-id/secret（沙箱可用桩值）
pet.merchant.application.enabled=true      # + open-cities[0]
pet.merchant.subject.enabled=true          # + MERCHANT_SUBJECT_* 密钥
pet.merchant.protection.enabled=true       # + MERCHANT_PROTECTED_* 密钥
pet.merchant.application.notifications-enabled=false
pet.outbox.enabled=true                    # + owner;outbox 表已建
pet.service.query.enabled=true
pet.service.command.enabled=true
pet.service.review.notifications-enabled=false
pet.store.query.enabled=true
pet.schedule.query.enabled=true
pet.schedule.protection.enabled=true
pet.order.creation.enabled=true
pet.order.expiry.enabled=true
pet.order.expiry.worker.enabled=false      # E2E 不开后台自动关闭
pet.payment.foundation.enabled=true        # + lakela.channel-time-zone 等
pet.payment.dispatch.enabled=true          # + 沙箱 environment/凭证/parameterKeyPath/notify-url
pet.order.auto-confirm.enabled=true
pet.order.auto-confirm.worker.enabled=true
pet.order.merchant.enabled=true            # + protection-key
pet.order.merchant.http.enabled=true
pet.order.merchant.worker.enabled=true     # 45号:HTTP 要求 worker+auto-confirm 全开
pet.order.reschedule.enabled=false
pet.verification.credential.enabled=true   # + key-id/encryption-key/lookup-key
pet.verification.credential.http.enabled=true
pet.verification.completion.enabled=true
pet.verification.completion.http.enabled=true
pet.refund.application.enabled=true        # + protection-key + reason-codes
pet.refund.application.http.enabled=true
pet.refund.application.worker.enabled=false
pet.refund.late.enabled=true               # ★ F-1 互锁:outbox+merchant 下必须开
pet.aftersale.enabled=false
```

注意：该组合里 `refund.late.enabled=true` 不是可选项——关掉它就复现 PRF-#133 启动失败。E2E 服务器在源码注释中原样记录了这条组合约束。

### 档 ② 最小生产起步

目标：能上线"浏览→下单→真实支付→10 分钟占位自动关闭→迟到支付自动全额退款"最小闭环；不含商家接单/核销/售后/改期/员工/通知（这些默认关，不违反任何 guard）。在档 ① 基础上**收窄**：

```
保留(true)：auth.admin、auth.c、merchant.application(+subject+protection)、
  service.query、service.command、store.query、schedule.query(+selection)、
  schedule.protection、order.creation、order.expiry(+worker=true 生产必开)、
  payment.foundation、payment.dispatch(真实凭证)、refund.late(+worker=true)、
  outbox
保持(false)：merchant.application/staff/service.review 的 notifications-*、
  staff.*、staff-member、private-assets、cover-signing、schedule.command、
  order.auto-confirm.*、order.merchant.*、order.reschedule.*、
  verification.*、refund.application.*、aftersale.*、notification.delivery
```

理由：`refund.late(+worker)` 与 `outbox` 同开是 F-1 互锁下的合法态且为迟到支付硬规则（订单保持关闭、真实支付金额自动全额原路退款）所需；`order.expiry.worker` 是占位 10 分钟自动关闭的生产前置。其余域默认关闭不触发任何 guard，后续按档 ③ 逐个补开。

### 档 ③ 逐域启用顺序（生产从最小集走向全量）

每一步之后的组合都必须仍满足 §1 依赖与 §2.1 矩阵；顺序按依赖自底向上：

1. **通知底座**：`pet.notification.delivery.enabled`（+真实微信适配器 bean；注意与商家通知联动）。
2. **商家通知**（可选先行）：`pet.merchant.application.notifications-enabled`（事件已在 outbox 积压，开启即补投）。
3. **接单链**：`pet.order.auto-confirm.enabled` → `pet.order.auto-confirm.worker.enabled`（先开任务，再开执行）→ `pet.order.merchant.enabled`（+protection-key）→ `pet.order.merchant.worker.enabled` → `pet.order.merchant.http.enabled`（guard 要求 auto-confirm.worker 同开）。★ 此时 refund.late 必须已开（档 ② 已含），否则 F-1 启动失败。
4. **核销链**：`pet.verification.credential.enabled`（+三密钥；guard 要求 auto-confirm+merchant 已开）→ `pet.verification.credential.http.enabled` → `pet.verification.completion.enabled` → `pet.verification.completion.http.enabled`。
5. **退款申请链**：`pet.refund.application.enabled`（+protection-key/reason-codes；guard 要求 merchant+auth.c）→ `.http.enabled` → `.worker.enabled`。
6. **售后链**：`pet.private-assets.enabled`（售后证据依赖）→ `pet.aftersale.enabled`（guard 要求 refund.application+verification.completion+private-assets+auth.c）→ `pet.aftersale.worker.enabled` → `pet.aftersale.http.enabled`（要求 auth.admin）→ 按需 `pet.aftersale.refund.enabled`。
7. **改期与评价**：`pet.order.reschedule.enabled`（guard 要求 schedule.protection+payment.foundation+auto-confirm+merchant）→ `pet.order.reschedule.http.enabled`；`pet.review.enabled`（guard 要求 auth.c）→ `pet.review.http.enabled`。
8. **排期写/员工域**（相对独立，可并行）：`pet.schedule.command.enabled`（+http/migration）→ `pet.merchant.staff.enabled` → `pet.merchant.staff-identity.enabled` → `pet.merchant.staff-member.enabled`（+UserPhoneVerificationApi bean + migration）→ `pet.verification.staff-identity.enabled`（要求 staff-identity）→ `pet.merchant.staff.notifications-enabled`。
9. **素材/封面**：`pet.private-assets.enabled`（若未在 6 开）→ `pet.service.cover-signing.enabled`（必须与 private-assets 同开）。

## 4. 维护规则

1. 任何切片新增/修改/删除 `pet.*` 布尔开关，必须在同一 PR 更新本文档总表与（若影响组合合法性）§2 矩阵及 §3 推荐档。
2. 新增 `IntegrationEventConsumer` 的消费者不得返回条件性空 `eventTypes()`（F-1 教训：空订阅在 `OutboxDispatcher` 构造期整体炸启动）；确需"装配但不订阅"时改为不注册 bean。
3. 新增 guard 类校验时优先复用既有 `switchValidation` 风格（启动期 `IllegalStateException`，信息中点名缺失开关），并同步 §2.1 表。
4. 本文只覆盖 pet-boot 主装配树；测试域专属开关（如 E2E 夹具属性）不在此列。
