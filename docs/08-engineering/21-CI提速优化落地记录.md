# 21. CI 提速优化落地记录（2026-10-09 ~ 10-10）

> 依据：[PingCode《CI 流水线构建速度慢的优化方法》](https://docs.pingcode.com/insights/j9h7lpj8h44f45l8lg14a1cj)（先减无效工作 → 合并重复步骤 → 串行改并行 → 性能提速）。交付物：PR #139（merge commit 885b0a2，仅改 `.github/workflows/ci.yml`）。

## 1. 诊断结论（基线实测）

基线 run 37890901513（2026-10-09，PR 全量）：**backend job 43m21s 一枝独秀**（≈整条 CI），miniapp 1m43s、web 1m20s、contract-smoke 1m15s、inventory/policy 各 ~8s。近 12 次 run 全量 43~62 分钟；叠加 PR 迭代时过期 run 不取消导致的排队（backend 排队 30-40 分钟常态）。

结构性问题：无 concurrency 取消；无路径过滤（改 .md 也全量）；三处 Node 环境无 npm 缓存；Playwright Chromium 每次全新下载；web-build 构建两遍（gate 与 `npm test` 各一次 typecheck+vite build）；全部 job 无 timeout。

## 2. 已落地改动（PR #139，commit f8eafff）

1. **concurrency**：PR 按 PR 号分组、新 push 取消过期 run；develop push 每个 run 独立分组，不取消不排队（保住合并验收六项绿证据）。
2. **changes job**（dorny/paths-filter@v3，仅 PR 事件）：按路径分类门控六 job；push 到 develop 一律全量（changes 跳过，下游以 `result=='skipped'` 放行）。未归类路径 `other=true` 触发全量，宁多跑不漏跑。
3. **六 job id/名称不变**（分支保护与六项绿口径不变）；job 级 `if:` 跳过（skipped 的 required check 视为通过）。
4. **缓存**：三处 setup-node npm 缓存；Playwright Chromium actions/cache；contract-smoke pip 缓存。Maven 缓存原有。
5. **web-build 去重**：`npm test` → `npx playwright test`（gate 已构建，dist 供 preview webServer；本地 scripts 不变）。
6. **timeout-minutes**：backend 60 / web、miniapp 25 / 其余 10。

### 路径分类的关键耦合（改 ci.yml 者必读）

- `backend` 触发集：`backend/**`、`docs/03-database/**`（**MySQL 测试基类直接执行该目录 schema**）、frontend-miniapp 的 `package.json`/`package-lock.json`/`tsconfig.json`/`src/consumer/tests/**`/`src/shared/tests/**`（**pet-boot 两条 node 链集成测试**：CFrontendHttpTest → backend-chain.ts、MerchantApplicationLifecycleHttpTest → merchant-http-integration.ts）。
- `contract` 触发集：`e2e/**`、`docs/00-ssot/**`、`docs/04-api/**`、`planning/ccr/**`（test_auth_contract.py 读 AUTH-001/examples.md）。
- `web`/`miniapp` 含 `backend/tools/**`（run-frontend-gate.py 是两 job 的执行入口）。

## 4. `-T 1C` 实验结论：放弃

run 37922615049 失败于 `pet-id-core` 的 `IdProviderProcessMySqlTest`：子 JVM（IdProviderProcessProbe）在 SingleFlightLane 撞 `OPERATION_TIMEOUT`、Child exited before READY。机制：并行 reactor 下多模块测试争抢 CPU 与共享 MySQL 服务容器，子进程探针的有界等待窗口被挤爆；串行两轮该测试均绿，属机制性不兼容而非随机 flake。按灰度协议不重试，force-push 回退。

## 5. 遗留：两个时间敏感测试（后续 backend 提速的前置）

1. `MerchantOrderHttpAcceptanceTest.pastDeadlineIsRejectedOverHttpWhileTheScheduledTaskStaysEligible`（pet-boot）：fixture 时钟钉到 paidAt+35min 后，异步自动接单 worker 同时具备资格，慢 runner 上两次手工断言（L191/L193）的第二次输给 worker（期望 ORDER_CONFIRM_DEADLINE_PASSED 实得 ORDER_STATE_NOT_ALLOWED）。串行下已出现一次（run 37912504355 attempt 1）。修法建议：测试内暂停/禁用 worker，或如相邻 L203 测试那样等待决策后再断言。
2. `IdProviderProcessMySqlTest`（pet-id-core）：子进程探针超时余量过小，任何并行化/负载放大都会触发。修法建议：放大探针 OPERATION_TIMEOUT 余量或改为无界等待+外层超时。

两者修复后可再试：`-T 1C`，或按模块分组双 job（pet-boot 单独一条）避开同容器争抢。backend 43min 长杆的主体是 pet-boot 26 个测试类多次启动 Boot 应用 + 每测试建删 MySQL 临时库，属测试工程改造范畴。

## 6. 语义变化（知情确认）

纯文档 PR 不再产生 backend 绿记录（内容对后端无影响，逻辑等价，记录粒度变粗）；push 到 develop 保持每次全量兜底。C 端 PR 只改 frontend-miniapp/src（不动两条链脚本）时 PR 阶段跳过 backend，链脚本级破坏由合并后 develop 全量 CI 兜底发现。
