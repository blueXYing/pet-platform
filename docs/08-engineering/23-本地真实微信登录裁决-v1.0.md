# 23 · 本地真实微信登录裁决（v1.0，2026-11-18 用户裁决）

## 结论

**本地/开发环境（含 E2eCoreLoopServer 验收链）一律走真实微信登录**：真实
`jscode2session` 换取真实 openid、真实 `getuserphonenumber` 获取真实手机号；
**不再把任意 wx.login code 映射到种子账号（138****0100 / 710100）**。CI 与无凭据
环境保留旧种子映射作为回落，行为由环境变量开关决定。

## 环境变量（Windows 用户级，已设置，跨 worktree/WSL 沿用）

| 变量 | 值（示例） | 说明 |
|------|------------|------|
| `PET_WX_APPID` | `wxc12540a8f32b372c` | 小程序真实 appid；DevTools 工程 appid 必须一致（code 与 appid 绑定） |
| `PET_WX_APP_SECRET` | （秘钥，勿入库） | 仅存于本机用户环境变量；`WSLENV` 带 `/u` 标志透传进 WSL |

- 秘钥**永不进源码/文档/日志**（生产装配本就如此：`pet.auth.c.wechat.*` 部署期注入）。
- 两变量齐备 → E2eCoreLoopServer 注册真实 `WechatMiniApiProvider`（生产实现，
  jscode2session + 手机号 + stable access token 内存缓存）；同时**不再注册**
  种子手机假件（`UserPhoneVerificationApi` 用生产实现按用户手机存储判定）。
- 两变量缺失 → 回落旧假映射（任意 code → 种子身份；手机号接受 `phone:1xxxxxxxxxx`
  测试码）。CI 依赖该路径。

## 行为变化（真实模式下）

1. DevTools 里 wx.login 产生真实 code → 后端真实换取 openid → **首次登录自动建新用户**，
   手机号未绑定时 `nextStep=PROVE_IDENTITY`，走小程序手机号授权按钮完成绑定。
2. 种子数据（E2E体验商家 710301 等）属于种子假身份——真实用户**不是**该商户 OWNER：
   - 消费者链路（浏览/下单）对真实用户完全开放；
   - 商家工作台需真实用户走「成为商家」申请（运营台可审）或店员邀请绑定。
   - 纯视觉/联调仍可用页面 `?preview=1` 夹具，不算"伪造登录"。
3. 后端出网访问 `api.weixin.qq.com`（国内直连；如遇代理环境由系统路由处理，
   `pet.auth.c.wechat.api-base` 可覆盖）。

## 执行位置

- `pet-boot/src/test/java/com/petplatform/boot/e2e/E2eCoreLoopServer.java`：
  `PET_WX_APPID/PET_WX_APP_SECRET` 条件装配（真实 Provider vs 种子映射）。
- `frontend-miniapp/project.config.json`：appid=wxc12540a8f32b372c（本地文件，
  沿惯例不提交）。
- 启动脚本 `/tmp/start-e2e-server-d128.sh` 显式透传两变量（源：
  `.zcode-tmp/start-e2e-server-d128.sh`）。

## 红线不变

- 手机号只信任微信侧换取（`exchangePhone`），从不信任请求体；
- appSecret/session_key 永不落日志（生产 Provider 注释与本裁决共同约束）；
- 脱敏展示（`138****0100` 形态）是**展示规则**，与"真实手机号获取"不冲突。
