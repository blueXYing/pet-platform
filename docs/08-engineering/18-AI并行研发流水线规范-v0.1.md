# 宠物平台 V1.0 AI 并行研发流水线规范 v0.1

> 定位：作为 ChatGPT Work 后续建立正式工程协作制度的输入草案。
> 本文只定义 AI Agent、GitHub Issue、Git Worktree、Codex Thread、PR、CI、合并与发布流程，不修改任何产品规则。
> 产品规则优先级仍为：SSOT > 最终 PRD > 技术基线 > Schema / API / Event / Scheduler > 测试矩阵。

## 1. 研发运行模型

```text
ChatGPT Work
= PM / Architect / Documentation / Planning

GitHub
= Backlog / Issue / PR / CI / 审计中心

Codex
= 临时 AI 工程师执行单元

Git Worktree
= 每个任务独立代码工作区

Repository
= 项目长期事实与工程记忆
```

核心原则：

```text
第一层：Project / SSOT       项目长期业务与技术事实
第二层：GitHub Issue         具体任务长期事实
第三层：AGENTS.md + Role     AI 员工岗位规则
第四层：Git Worktree         代码隔离
第五层：Codex Thread         一次任务的临时执行上下文
```

因此：
- 角色长期存在；
- Issue 有明确生命周期；
- Worktree 按任务创建与删除；
- Codex Thread 按任务创建与关闭；
- 不使用“一个 AI 员工 = 一个持续数周的永久长对话”。

## 2. 初始 6 个 AI 角色

### AI-01 Backend Core Engineer
负责：
`pet-common`、`pet-user-*`、`pet-merchant-*`、`pet-service-*`、`pet-schedule-*`、Auth/RBAC、基础设施。

### AI-02 Transaction Backend Engineer
负责：
`pet-order-*`、`pet-payment-*`、`pet-refund-*`、`pet-verification-*`、`pet-aftersale-*`。

### AI-03 C-End Frontend Engineer
负责：
统一Taro React小程序的用户工作区，`frontend-miniapp/src/consumer/**`；共享壳与shared由C-End唯一编辑，具体范围以Issue为准。本期不做App。

### AI-04 Merchant Frontend Engineer
负责：
同一小程序商家工作区，`frontend-miniapp/src/merchant/**`；不创建第二套应用壳。

### AI-05 Admin Frontend Engineer
负责：
React运营网页，`frontend-admin/**`。

### AI-06 QA / Integration Engineer
负责：
`tests/**`、`e2e/**`、ArchUnit、Integration、Contract、Concurrency、Failure Injection。

## 3. 任务单位：GitHub Issue

推荐编号：

```text
CORE-xxx
TX-xxx
C-xxx
M-xxx
ADM-xxx
QA-xxx
CCR-xxx
```

其中 `CCR` = Contract Change Request。

每个 Issue 至少包含：
- Title
- Owner Role
- Background
- Dependencies
- Allowed Modules
- Forbidden Modules
- Related SSOT / API / Event / Schema
- Acceptance Criteria
- Required Tests
- Definition of Done

推荐任务粒度：

```text
2~8小时：理想
1~2天：可接受
超过3天：继续拆分
```

## 4. Worktree 生命周期

Worktree 按任务创建，不按角色永久保存。

示例：

```bash
git worktree add ../wt-tx-005 -b feat/TX-005-late-payment-refund develop
```

生命周期：

```text
Issue READY
→ 创建 branch
→ 创建 worktree
→ 新建 Codex Thread
→ 实现
→ 测试
→ Commit
→ PR
→ CI
→ Review
→ Merge develop
→ 删除 worktree
→ 关闭 Thread
→ Issue DONE
```

删除示例：

```bash
git worktree remove ../wt-tx-005
git branch -d feat/TX-005-late-payment-refund
```

## 5. Branch 规范

```text
main
develop
feat/CORE-xxx-*
feat/TX-xxx-*
feat/C-xxx-*
feat/M-xxx-*
feat/ADM-xxx-*
test/QA-xxx-*
fix/BUG-xxx-*
chore/*
```

AI Worker 禁止直接 push `main` 或 `develop`。

## 6. 文件所有权

普通 Worker 只修改当前 Issue 的 `Allowed Modules`。

默认保护文件：

```text
docs/00-ssot/**
AGENTS.md
根 pom.xml
OpenAPI 主契约
核心共享 Event Contract
全局数据库 Migration 基线
.github/**
CODEOWNERS
```

如果 Worker 发现必须修改保护文件：

```text
不得自行扩大范围
→ 创建 CCR
→ Work / Architect 审核
→ Contract Owner 修改
→ 合并后原任务继续
```

## 7. Contract First

前后端必须并行，不等待后端全部完成。

```text
SSOT
↓
OpenAPI / HTTP API
↓
Backend 实现
+
C端 Mock / SDK
+
商家端 Mock / SDK
+
运营端 Mock / SDK
```

前端基于 OpenAPI 生成类型/SDK并使用 Mock Server，联调时再切真实 Backend。

## 8. Codex Thread 启动模板

```text
你是 <Role Name>。

执行 Issue：<ISSUE-ID>。

开始前：
1. 阅读 AGENTS.md；
2. 阅读 .ai/roles/<role>.md；
3. 阅读当前 Issue；
4. 阅读 Issue 引用的 SSOT/API/Event/Schema/Test；
5. 检查依赖 Issue 是否已完成。

约束：
- 只完成当前 Issue；
- 不修改 Forbidden Modules；
- 不自行修改产品规则；
- Contract 缺陷走 CCR；
- 不直接 push main/develop。

完成前：
1. 运行单元测试；
2. 运行相关集成/P0测试；
3. 执行架构检查；
4. 输出修改文件；
5. 输出测试结果；
6. 输出遗留风险；
7. 准备 Commit / PR。
```

## 9. PR 与 CI

PR 至少包含：
- Issue
- Scope
- Changed Modules
- SSOT Impact
- API Impact
- DB Impact
- Event Impact
- Tests
- Concurrency Risk
- Backward Compatibility
- Rollback
- Known Risks

CI 至少执行：

```text
compile
unit tests
ArchUnit
module integration tests
DB migration smoke test
OpenAPI parse
API contract check
affected P0 tests
frontend typecheck/lint
```

支付、退款、核销、排期容量、优惠券、积分、售后、AsyncTask、Outbox 必须增加专项测试。


## 11. QA 左移

QA 与开发并行。

例如：

```text
Transaction:
TX-005 迟到支付自动退款

QA:
QA-TX-005
- 正常测试
- 重复回调
- PAYMENT_EXPIRE × callback 并发
- refund UNKNOWN
- consumer重复事件
```

现有 171 条测试矩阵逐步转换为 QA Backlog。

## 12. ChatGPT Work 的职责

Work 负责：

```text
项目计划
架构治理
文档归一
Backlog拆解
依赖分析
Ready Queue
Blocked Queue
一致性审计
Release计划
```

Work 不承担一个长期直接修改所有代码的“大开发线程”。

## 13. Codex 的职责

Codex 负责：

```text
领取一个 Issue
→ 在隔离 Worktree 中实现
→ 运行测试
→ 生成 Commit / PR
→ 结束任务
```

## 16. 核心原则

```text
对话不是项目记忆，代码仓库才是
AI员工不是永久聊天，Role才是
Worktree不是长期分支，Issue才是生命周期
AI不是随意并行，Contract + Ownership + CI 才能支撑并行
```
