# SVC-STORES-QA 权限反例矩阵（服务管理 / 门店读侧）

日期：2026-09-22。Owner：角色D（QA/集成）。分支 `codex/qa-svc-stores-20260922`。

定位：**只列反例（必须拒绝的组合）**，正例权限见 PRD/契约。本矩阵是未来写入方（ADM-001"服务操作"、M-002 消费）与门店读切片的验收输入，当前多数条目 BLOCKED 于写入方未交付；已可执行的反例标注了证据。

依据：商家端 PRD（最终基线）角色权限矩阵——主账号（负责人）：订单处理✓/排期维护✓/服务项目✓/核销✓/售后✓/评价回复✓/员工管理✓/店铺资料✓/经营数据✓；**核销员：服务项目✕**（订单处理✓、核销✓，其余✕）；"子账号登录只可见被授权范围内的功能"；SSOT"子账号不得代签或查看主账号签约信息"。运营端 PRD：服务上架闭环=商家创建草稿→提交→运营审核（上架/驳回）→运营保留强制下架权；"下架后重新上架必须重新过审"；22号运营权限裁决（单运营、超管=全 V1 已批准业务权限，禁止登记的动作对超管同样不开放）。12号错误注册表：403 COMMON_FORBIDDEN / 404 COMMON_NOT_FOUND（防枚举统一）。SSOT §24、MFA 取消不影响 RBAC（SSOT §25）。

## 1. 通用规则（先读）

- 写操作一律要求 X-Request-Id（8-4-4-4-12 UUID）+ requestId 幂等（23号）；反例矩阵中的"403/404"均为**无业务副作用**（失败关闭、留审计）。
- 防枚举原则：跨商家归属的资源访问按契约统一 404（不暴露存在性），不返回 403+资源信息；**最终取 403 还是 404 以写入方冻结契约为准**，两栏都保留待复核。
- 门店/服务 C 端读路由对任何已登录 C 会话可见（无归属概念），不适用本矩阵；本矩阵针对**管理动作**。
