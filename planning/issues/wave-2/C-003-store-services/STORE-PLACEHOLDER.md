# C-003 门店契约占位规划（STORE-PLACEHOLDER）

日期：2026-09-22。状态更新（同日实施轮）：用户已原则批准 /c/stores 两读路由（v0.2 草案，角色B实现中）——本页所列"商家详情页的门店信息摘要"已按九字段契约绑定（店名/地址/掩码电话），门店列表页（`consumer/pages/store-services/stores`）已实现，详情 404 不可访问态已接入；**评分/月售/距离/标签/简介/营业时间/评价/促销仍维持下表"本轮不做"口径**（各自契约未冻结，继续按 designSamples 呈现并登记）。原始规划留档如下。

## 依赖该契约的范围（本轮不做）

| 范围 | 设计源 | 处置 |
|---|---|---|
| 服务tab 页面本体（搜索框/分类宫格/商家钜惠横排/优质商家信息流/筛选排序） | `110:480`、`690:6370` | 契约批准后另切片实现；本轮已有 2x 截图+结构摘要 |
| 商家详情页的门店信息摘要（店名/评分/月售/距离/标签/简介/地址/营业时间/电话/头图/头像） | `690:6660` 上半区 | 页面已按设计样例渲染（`designSamples.store`，仅视觉）；契约冻结后替换为真实字段绑定，**不预设字段名** |
| 用户评价摘要 | `690:6660` 评价区 | 同上（评价域契约另行 CCR） |
| 促销/营销文案 | `690:6660` 促销条 | V1 无营销工具，是否裁剪待裁决（INVENTORY D2） |

## 契约冻结后的接入点（已在代码中预留，无需返工）

- 页面数据加载仅经 `ServiceCatalogDeps`（`src/consumer/service/model.ts`）；门店信息不与该接口耦合。
- `designSamples.store` 是唯一门店文案出口——替换为真实仓储时只改一处；`designSamples.sold`（已售N）与 `listDescription`（列表描述）同样集中登记为契约缺口（列表投影无对应字段）。
- 路由参数：`index` 页已接受 `storeId`（雪花 String），门店详情契约到位后同一参数可直接复用。

## 需在门店契约 CCR 中一并裁决的字段缺口（页面视角）

1. 列表项：评分、月售、距离、主营标签、热门服务+价格+已售（服务tab 卡片）；排序/筛选参数（PRD §5.1.13 有定义，传输形状未定）。
2. 详情项：营业时间、联系电话、简介、头图/头像 URL、促销文案位是否属于 V1。
3. 已售数量统计字段（服务卡"已售N"）——PRD §5.1.14 有定义，服务域读契约未含。
