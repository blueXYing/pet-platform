# CCR-C002-PET-DISPLAY-001：宠物档案展示字段缺口

状态：PROPOSED，未批准。日期：2026-09-16。关联：C-002 / PR34、CCR-W2-API-001。请求 USR-001 / Contract Owner 处理。

## 问题与现有依据

Figma `bp2vpcjjA5vZbHvtKkA8wl`、版本 `2397539525915641008` 的 `78:2817`、`78:3076`、`95:1481/95:1844` 包含宠物芯片号、疫苗/驱虫名称和日期。现行 PetView 有 avatarUrl、petType 和 vaccineStatus，但没有芯片号或记录明细。头像读取字段已有契约，不能以“上传契约未接入”为理由忽略 avatarUrl。

## 请求裁决（不在本 PR 自行定义接口）

1. 芯片号是否纳入 V1；若纳入，确定可空性、格式、长度、编辑权限与请求字段。
2. 疫苗/驱虫记录查询字段、关联 petId、时间格式、状态来源、排序/分页，以及缺数据和无记录的区别。
3. 首页最近记录标签的选择规则是否由后端提供；避免前端私自按样例日期推断业务状态。
4. petType 创建必填/默认规则及表单入口；头像上传仍由既定 OSS/USR 接口承接。

## 本次安全边界

- 不修改 HTTP/JSON DTO、Schema、Event、Scheduler 或 backend。
- 可读 avatarUrl 优先显示，预览内缺头像时才使用相应源图或首字占位。
- 样例芯片与记录仅归属设计中的豆豆；其他宠物不复制豆豆的健康记录，使用空值/空态。
- 展示记录由独立 previewSupplement 提供，仍是仅内存的视觉样例，不提交、不宣称真实接入。
- 接口批准并实现后，由后续任务替换该预览数据来源并覆盖真实 CRUD、上传、记录排序及会话失效测试。
