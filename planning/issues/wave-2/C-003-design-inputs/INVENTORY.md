## 4. 裁决建议：商家端"商品管理"frame 是否即 M-002 服务项目管理设计源

**建议：是（推荐采用 10:5255 + 11:5768 作为 M-002 服务项目管理页设计源），但存在 6 处需按 PRD/契约修正的字段级差异，需人工确认后实施。**

依据：
1. 列表 8 项全部是**服务**（猫咪洗澡+基础护理/狗狗美容造型/宠物疫苗接种（狂犬）/猫咪绝育套餐/狗狗寄养（每日）/宠物体检基础套餐/猫咪上门喂养/狗狗训练课程），无一实物商品；V1 明确不做套餐/次卡/普通商品，商家端无其他服务管理 frame，"商品"在该稿语义上只能是服务项目。
2. 表单字段与 M PRD §5.5 字段表高度对应：商品名称↔服务名称、价格（元）↔销售价格、划线价（可选）↔划线价、商品分类↔服务分类、适用对象↔适用宠物类型、履约方式↔履约方式、服务时长(分钟)↔服务时长、是否需要核销↔是否需要核销、套餐上架开关↔状态（上架/下架）、头图↔封面图、商品描述/套餐详情↔服务说明。
3. 列表卡片右上角蓝色/灰色圆形按钮对应上架/下架状态切换。

需人工确认的修正项（设计稿超出 V1 已批范围）：
1. **售卖模式"直接售卖"**：V1 服务形态固定"单次预约服务"（M PRD §5.5），应固定为预约服务，裁掉"直接售卖"选项；
2. **套餐包含项目**（洗澡/剪毛/驱虫/…pills）：PRD 字段表无此字段（套餐概念不在 V1），建议裁剪；
3. **履约方式三选项**（上门接送/无接送/只送不接）与冻结契约 `FulfillmentType = IN_STORE | PICKUP_DELIVERY`（到店型/上门接送型）不一致，"只送不接"无契约，需按契约两值实施或走 CCR；
4. **商品分类 pills**（洗护/美容/医疗/寄养/其他）与 C 端统一服务字典 11 类（宠物美容/遛狗陪护/宠物寄养/宠物训练/上门喂养/兽医助理/小宠寄养/异宠上门喂养/异宠健康检查/绿植养护/植物代养）不一致，需按统一字典实施；
5. **审核状态**：M PRD §6.3 状态机含 待审核/审核驳回/售罄；已批 Schema `service_item.status` 仅 DRAFT/ACTIVE/OFFLINE，列表 frame 未呈现状态机全部状态，实施以已批 Schema 为准，状态机超出部分留待写入方 CCR；
6. TabBar 同 D1 差异；添加商品 frame 无"服务人员要求/备注/售后说明"字段（PRD 可选字段），是否补齐待裁决。
