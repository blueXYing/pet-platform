# CCR-SCH-SLOT-001 排期模型改为「全店统一时间槽 + 单容量池」

- 状态：APPROVED（2026-11-13 用户裁决，见 §8；实施待排期）
- 日期：2026-11-13
- 提出方：用户（商家端排期可用性裁决：100 个服务逐个开窗不可用）
- 关联：SSOT §12.1/§12/§29；PRD29（docs/01-prd/29-排期人员容量与维护人工裁决补充-v1.0.md）；
  Contract 34/36/38/39/53；06号 SQL §schedule_availability_window；37号（window_kind 增列）；
  `planning/progress/2026-11-04/merchant-figma-restore/pending-issues.md` P-14（本裁决）/P-11b（降级）
- 当前模型：窗口身份 = storeId+serviceId+windowKind（53号 §3），容量/重叠/占用全部按
  "店×服务×方式"三键组织
- 是否涉及产品裁决：**YES（已裁，§8）**

## 1. 问题

按服务开窗在服务数量多时不可用：100 个服务 = 逐服务逐窗配置，商家操作量线性爆炸。
用户 2026-11-13 验收排期页时指出并直接裁决改为共享槽模型。

## 2. 新模型（裁决后）

| 维度 | 旧 | 新 |
|---|---|---|
| 窗口身份 | storeId+serviceId+windowKind | **storeId+时间区间**（全店共享） |
| 窗口类型 | GENERAL/PICKUP/RETURN 三类 | **无类型**（一套统一槽） |
| 容量 | 每窗容量按服务归属独立 | **全店单容量池**：槽容量 N，任何服务的有效预约都占，占满即 SOLD_OUT |
| 重叠校验 | 同店同服务同 kind 不重叠 | **同店不重叠** |
| 员工能力集合 | 按服务授权（SCHC-2） | **不变**（按服务授权保留） |
| SOLD_OUT 派生态 | 系统按占用派生 | **不变**，占用口径=该槽上全店有效 claim 数（跨服务合计） |
| 接送 120 分钟规则 | 预约时服务端强校验（PRD29 §9） | **不变**——本就不在开窗层校验（"开窗接口不遍历组合校验"原文），统一槽无影响：接送单的上/返程两个时间点各自命中开放槽即可 |
| 履约方式×kind 写入校验 | IN_STORE 仅 GENERAL 等 | **删除**（无 kind 维度） |

## 3. C 端可约语义（关键设计）

`GET /api/v1/c/services/{serviceId}/availability` 路由与**响应形状不变**（分钟级 slots
列表），计算来源变为：

- 候选时段 = 全店开放槽（时间轴）
- 某服务在某槽"可约" ⇔ 该服务具备能力且排班覆盖该时段的员工数 ≥ 1
- 每服务的**有效容量**仍可按 `min(槽容量, 该服务可用能力员工数)` 口径呈现（SSOT §12
  容量公式的服务视角保留，仅"商家配置容量"锚点从服务窗变全店槽）
- C 端前端预约页**零改动**（消费的 slots 形状不变）

## 5. 不变项（防走样）

- 分钟级半开区间、无固定 60 分钟槽（SSOT §12.1 保留）
- 禁周模板三字段（dayOfWeek/repeatWeekly/copyNextWeek）——P-11b 降级为可选便利项（见 §7）
- 幂等/审计/乐观并发/占用保护/批量 200 上限/SOLD_OUT 派生态全链不变
- 员工排班（staff_availability_window）与能力集合模型不变

## 6. 风险

1. 接送类服务与到店服务共享容量池：高峰期到店单可能挤占接送容量（反之亦然）——
   用户已知情选择单池（§8.2）；如运营期发现失衡，可再提 CCR 加每 kind 预留。
2. 38/39 预约链的窗口命中逻辑需全量回归（时间点命中的槽从"该服务窗"变"全店槽"）。
3. 既有测试/种子大量钉子在"按服务开窗"模型上，返修轮数预期 2-3 轮 CI。

## 7. 对 P-11b（周循环模板提案）的影响

统一槽后"逐服务逐窗开"的痛点头消失（一店一套槽，量级从 服务数×时段 降为 时段）。
P-11b **降级为可选便利项**：若商家仍希望"按周批量生成分钟级槽"，可后续单独立项；
本轮不实施、不再阻塞排期可用性。

## 8. 裁决记录（2026-11-13，用户）

1. **废除按服务排班**：排期改为全店统一时间槽，所有服务共享（起因：100 服务逐个
   设置排期不可用）。
2. **槽类型**：只留一套统一槽（不保留到店/上门接/返程送三分类）——比推荐项更激进，
   接送 120 分钟规则维持预约时校验。
3. **容量池**：全店单池（推荐项）——槽容量 N，任何服务预约共同消耗，占满即已约满。
