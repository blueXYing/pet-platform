# CCR-SCH-SLOT-003 周循环模板（读时展开 + 下单物化混合模型）

- 状态：APPROVED（2026-11-13 用户两轮澄清拍板："365 天都按这个 7 天循环来，而不是生成 365 个 7 天"）
- 日期：2026-11-13
- 提出方：用户（排期页验收第三轮）
- 关联：CCR-SCH-SLOT-001（统一槽）/002（批量生成）；SSOT §12.1 周模板禁令（本 CCR 修订）；
  53号；38号 booking hold
- 取代：CCR-SCH-SLOT-002 的"生效天数铺排"前端模式（batch-generate 命令与契约保留，
  作为手动批量入口；不再是周模板的保存路径）

## 1. 模型（读时展开 + 下单物化）

| 层 | 行为 |
|---|---|
| 存储 | 新表 `merchant_schedule_week_template`：store_id 唯一、7 天×段列表（每天 0..24 段 "HH:mm" start<end 不重叠、空=该天休）、version、created/updated。**持久配置，永不自动过期** |
| C 端可约读 | availability/selection 的 items = 真实窗口 ∪ 模板展开（对未来日期按周几展开虚拟段，仅展开到 now+maxDays 可约范围内；与真实窗口重叠的段去重） |
| **下单物化** | booking hold 命中模板段（该时刻无真实窗口）→ **同事务创建真实分钟级窗口**（容量=模板段容量）→ 在其上 claim。占用/SOLD_OUT/退款/改期保护链从此完全照常 |
| 商家改模板 | PUT 只影响"未来未物化"的展开；**已物化窗口（有预约的/商家手建的）一律不动**（用户 2026-11-11 原口径） |
| 商家窗口列表 | 列表=真实窗口；页顶提示"周模板生效中（周X: N 段…）"指向模板编辑 |

## 2. 为什么不破保护模型（红线论证）

- 所有**预约事实仍 100% 落在真实分钟级窗口**上（物化即建窗）——SCHC 守卫、SOLD_OUT 派生、
  退款释放、改期不变量、批量关窗全链不动；
- 模板只影响"未发生预约的未来"的**呈现**；任何段一旦被预约即固化成真实窗口；
- 无周期字段进入窗口表（dayOfWeek/repeatWeekly 禁令保持）；模板是独立配置面非窗口属性。

## 3. 契约变化（53号 v0.3 增补）

- `GET /api/v1/merchant/stores/{storeId}/week-template` → `{days:[{enabled,segments:[{start,end,capacity}]}×7],version}`（缺行=七天全休）
- `PUT .../week-template`（全替换+expectedVersion；改模板非减少可用性动作——已物化不动，reason 不需要）
- 38号 hold：增加"模板段物化"内部步骤（同事务 createWindow+claim），对外错误面不变
- SSOT §12.1 行修订："不做周期性**窗口数据结构**；周模板=独立配置面，读时展开、下单物化为真实分钟级窗口（CCR-SCH-SLOT-003）"

## 4. 容量口径

模板段自带容量（每段 {start,end,capacity}，默认 6）——替代 002 的全局容量输入（保留 batch-generate 的容量参数供手动批量）。

## 5. 影响面

Schema 新表（SQL53+V29）；schedule-biz（模板面/读侧并集展开/hold 物化钩子）；38号链回归；
商家前端（B 区草稿直存模板、保存不再铺排、折叠区顶部模板状态）；C 端零改动（slots 形状不变）；
CCR-002 的"生效天数"UI 移除（batch-generate 端点保留）。

## 6. 裁决记录（2026-11-13，用户）

1. 周模板=持久循环配置，365 天/跨年自动生效，**不需要任何再生成**。
2. 保留"下单物化"保护模型（预约落真实窗口，全部保护不变）——实现层设计，未单独裁决。
