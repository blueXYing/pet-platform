# S2 发号器设计：一页审批指南

状态：**PROPOSED / PENDING_REVIEW**。2026-09-14。所属既有CCR-W2-IDEMP-001 / PLAT-002。本次只新增生产实现设计，不重问已接受的Snowflake布局、epoch、ID String、金额和幂等方案。

**推荐一项决定：采用“MySQL永久高水位 + 独占续留 + 不重叠时间区间”的生产发号设计，并采用下方初始参数。** 数据库先记住某个worker已经预留到哪个毫秒，再允许进程在自己的区间内发号。进程重启或被接管后，旧区间整段作废，宁可留下空号，也不再使用。

| 谁负责 | 做什么 |
|---|---|
| 我负责 | 区间与事务算法、暂停/重启/回拨安全审查、后续源码/迁移设计与真实故障验证；不把数据库细节交给你猜 |
| 你只审批 | 是否接受这一个新增设计包及初始参数；原已接受两项不重复审批 |
| 推荐理由 | 使用已有MySQL基线，不增加独立平台服务；多数ID在本地生成，数据库只续租/扩展小时间窗 |
| 主要代价 | 新增一张最多1024个worker状态行的技术表及独立实现模块；依赖高水位不可丢失；故障/换进程会停发或等待，并允许空号 |
| 必看 | 本页；[故障例子](s2-examples.md) E02～E06；技术备查[具体设计](s2-id-provider-design.md) §3～7与§10 |

| 参数 | 推荐值 | 作用 |
|---|---:|---|
| nextId总等待预算 | **1秒，沿用已接受约定** | 包括等连接/锁/提交、追时间、序号耗尽；无法调度的暂停不保证准时回包，恢复后检查预算 |
| 预留窗口W | 5秒 | 减少数据库写；换进程丢弃未用区间 |
| 剩余窗口触发补充 | 1秒 | 只提前保留一个连续窗口，不无限预取 |
| 数据库owner租约 | 10秒 | 串行控制新的授权/扩窗；不是立即杀停旧进程的保证 |
| 后台续租周期 | 2秒 | 检测失联/保持当前owner资格 |
| 本地租约安全余量 | 1秒 | 从发请求前单调时钟算9秒本地截止，不能从ACK到达重算10秒 |
| DB/应用UTC采样容差 | 250毫秒 | 检测明显偏差/跳变后停发；不是唯一性证明依赖的全网同步假设 |
| 最大预留超前 | 10秒 | 防反复崩溃把高水位烧到很远；超过不分配、不再推高H |

正常运行下多数发号不访问DB；故障时优先停发。进程崩溃且租约尚在时，新进程通常要等余下租期；旧区间还在未来时也须等真实UTC追上。**10秒/5秒不是故障恢复SLA**，网络、DB恢复、时钟回拨可能使停发更久；单次请求仍按1秒预算失败，不偷偷延长。

安全承诺有明确前提：单一权威写库、已确认的高水位不丢不回退、同一内存发号状态不克隆。若数据库从旧备份恢复或可能丢提交，不能直接启动发号，必须先隔离旧进程、核实并恢复可信上界。数据库fence能阻止旧进程再扩窗，不能撤回已经生成但尚未返回的ID；不重复依靠区间互斥及区间内序号不复用。

**当前没有实现/DDL/迁移/环境改动，也没有生产唯一性或MySQL灾难测试结果。** 接受后还需根Work安排具体迁移与实现、权威Contract同步及真实故障验收；本设计PR合并仍按审批，不能直接宣称PLAT-002/PLAT-004完整DONE。通用业务幂等表、旧业务requestId迁移、Provider/AUTH语义不包含在本次新增批准中。
