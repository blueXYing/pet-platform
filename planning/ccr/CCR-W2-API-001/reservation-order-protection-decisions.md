# SCH-003 / ORDER 六项联合契约批准回执（2026-09-24）

用户审阅[联合 CCR 六项推荐](reservation-order-protection-proposal.md)后明确回复：**“批准六项推荐方案”**。ROC-1～ROC-6 因此由候选改为 **ACCEPTED_CONTRACT_NOT_IMPLEMENTED**。规范正文见 [36 号预约与订单人员保护契约](../../../docs/04-api/36-Reservation-Order-Protection-Contract-v0.1.md)，产品规则同步到 [SSOT §31](../../../docs/00-ssot/01-SSOT-宠物平台V1.0-最终业务基线.md)。本回执的批准不等于接口、DDL、迁移、测试或生产开关已经交付。

| 编号 | 已批准的决定 | 性质 |
|---|---|---|
| ROC-1 | 同门店跨服务和两方向 claim 的完整人员可行性证明；商家当前指派固定，未指派仅作内部数学匹配；每原窗配置容量另证。可信事实下无解 409，事实不全或求解超预算 503。 | 技术保护合同 |
| ROC-2 | 一笔接送订单由同一名商家最终指派人员覆盖完整 PICKUP 与 RETURN 两窗，中间空档无需连续排班；不自动在 ORDER 写技术匹配人员。 | 产品语义与订单合同 |
| ROC-3 | 新到店预约须有一条同店同服务 OPEN GENERAL 原窗完整容纳按既有服务时长规则得出的实际预约区间；跨窗新单失败关闭。原窗 ID 与实际区间入 claim；历史跨窗不得伪造或自动取消。 | 新批准产品选择及关联合同 |
| ROC-4 | ORDER 预生成非空 orderId，SCH hold 与 ORDER 主单创建在同一顶层主库本地事务内双向绑定，失败整体回滚；外部支付在提交之后。 | 技术绑定合同 |
| ROC-5 | ORDER 按预约、按员工/门店提供同事务当前指派事实及全量完整性证明；两份当前指派不一致或在途订单缺活跃 claim 时失败关闭，生命周期用正式底层状态判定。 | 技术保护合同 |
| ROC-6 | 改期保留商家当前指派；原人员不能覆盖新时间时拒绝交换，原预约、原 claim、指派、改期次数和确认周期均保持。 | 新批准产品选择 |
