# CCR-MKT-003 首页运营内容位（热门服务 / 植物&异宠 / 宠友圈热门容器）

- 状态：用户已确认（2026-10-28）
- 关联：71 号契约 v0.2、CCR-MKT-001/002、CCR-COM-001
- 目标：首页「热门服务」「植物&异宠」不再由前端写死；运营在后台手动配置标题、文案、图片、落地目标和排序。模型预留 `sponsor_merchant_id` / `sponsor_store_id`，后续商家竞价只需增加竞价单与结算，不改变首页读取协议。

## 范围

1. 新增 `marketing_home_block` 及审核表：`position_code`、`template_code`、标题/副标题/标签、图片、落地目标、城市、赞助商家/门店、排序、生效窗口、状态、版本。
2. 运营接口：列表、创建、编辑、启用、停用；权限复用 `marketing.placement.read/manage`，写操作 `X-Request-Id` 幂等、append-only 审计。
3. C 端接口：`GET /api/v1/c/marketing/home-blocks?cityCode=` 返回当前生效内容位；空/失败整块隐藏。
4. 首页按 `templateCode` 白名单渲染：`HOT_SERVICE_FEATURE`（热门服务大卡）、`COMMUNITY_HOT`（宠友圈热门容器）、`EXOTIC_PLANT`（植物&异宠小卡）。图片由 `marketing_asset` 上传，前端不写死插画。
5. 热门服务由运营手动选择落地目标（服务目录/分类/门店/服务/活动）；不在本次实现自动销量推荐或竞价排序。
6. 宠友圈热门容器由运营配置标题/文案/图片和目标；容器下方的真实动态由 CCR-COM-001 的热门流提供；空流时容器隐藏或降级为纯入口，由 `templateCode` 决定。

## 不做

- 不做任意 HTML/可视化布局编辑器；模板仍由前端白名单提供。
- 不做竞价出价、扣费、结算；只预留赞助字段。
- 不做自动销量/评分推荐；后续需要时新增读模型。

## 验收

- 后台上传图片并创建三条内容位，启用后首页立即显示，换图/改文案不需要小程序发版。
- 内容位停用/过期/城市不匹配时前端隐藏；接口失败不阻塞首页。
- 点击热门服务进入服务目录/分类；点击植物&异宠进入对应分类关键词；点击宠友圈热门进入宠友圈。
- 写操作重复 requestId 返回同一回执；非法目标/模板/时间窗被拒绝。
