# CCR-SCH-STAFF-OFFLINE-001 取消系统化员工排班，容量=时段容量

- 状态：APPROVED（2026-11-16 用户拍板："员工排班让线下人员自己排，没必要和系统挂钩；时段容量是多少就是多少"）
- 日期：2026-11-16
- 关联：SSOT §12 容量公式/§29；PRD29；CCR-SCH-SLOT-001（统一槽）；53号 §4（员工排班 CRUD）；34号 SCHC（排班保护）
- 旧模型：实际可约容量 = min(时段容量, 有能力且排班覆盖该时段的员工数)；预约 hold 校验员工覆盖
- 新模型：**实际可约容量 = 时段容量**（就是商家填的数字）；不校验员工排班覆盖

## 1. 裁决

1. 员工排班归线下管理，系统不承载排班数据
2. 容量=时段容量，不做员工数 min
3. 预约 hold 不校验员工排班覆盖

## 2. 保留不变

- **员工能力授权**（54号）不变——"会不会做这个服务"仍在系统（核销/指派需要）
- **员工管理**（成员/详情/停用/启用/授权）不变
- 统一槽/周循环模板/批量生成/可预约范围/不可约日期——全部不变

## 3. 影响面

| 层 | 删/改 |
|---|---|
| SSOT §12 | 容量公式改"= 时段容量"；§29"可用人员须排班覆盖"条目废除 |
| PRD29 | 排班相关条款标注废除 |
| 53号 §4 | 员工排班 CRUD 路由删除（staff availability-windows GET/POST/PUT/close/open） |
| 34号 | SCHC 员工排班不变量简化 |
| 后端 | staff_availability_window 表保留（不删历史数据）但读写全移除；AvailabilityQuery/Selection 不再查员工覆盖；hold/swap 不校验排班 |
| 前端 | schedule 页"员工排班查询"区块删除；schedule/staff 子页删除或入口隐藏 |
| 测试 | 排班相关全族测试删除或迁移 |

## 4. 风险

- 员工请假不会自动降容量（商家改时段容量即可）——用户已知悉
