## 修复组织

沿用户既有多角色 GPT-6 Sol / xhigh 要求：排期与相关领域、订单与退款、支付三个编码角色，根任务整合、审计和门禁；按模块保留独立提交。已合并 PR 的历史不重写，修复在当前开发分支向前提交。本轮将整改纳入 #90 一并审阅，用户已明确扩大修复范围；PR描述必须同时披露退款实现及六个PR的持久层整改，不暗示历史PR已自动回滚或develop已修好。

SQL 进入各自 Owner 的 `resources/mapper/*Mapper.xml`，采用参数绑定；可复用的列/读取片段用 XML `<sql>/<include>`，集合用 `<foreach>`、条件用 `<if>/<choose>`，不使用 `${sql}` 转移 Java 拼装。Java 保留业务检查、事务、DTO转换。Mapper 使用原 DataSource，保留行锁、BINARY比较、版本谓词、幂等与错误处理；权威事实查询禁同事务缓存复用。

AGENTS.md 补入已生效的22号要求。CI新增 `backend/tools/check-persistence-style.py`：检查生产 JDBC执行器、Java SQL常量/文本块/相邻字符串拼接、MyBatis SQL注解/Provider及XML原样字符串替换。保留事务管理和连接元数据读取；测试与迁移脚本不在生产扫描内。负例测试验证门禁确实能拦截回退，空扫描失败。
